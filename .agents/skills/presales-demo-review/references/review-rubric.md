# 售前演示方案评审细则

## 结论等级

| 等级 | 含义 | 使用条件 |
| --- | --- | --- |
| 可直接用于售前 | 材料能独立讲清客户痛点、演示故事、数据与本体逻辑、最终价值 | 只需局部措辞或排版调整 |
| 小修后可用 | 主线成立，但局部缺少数据、图片、边界或输出动作 | 1-3 处补强后可面向客户 |
| 需结构性补强 | 有材料堆叠，但缺少清晰业务故事或闭环 | 需要重排章节、补对象模型或重写演示路径 |
| 不适合作为售前演示方案 | 像技术方案、产品清单或 AI 文案，客户难以理解价值 | 需要回到需求分析阶段重做 |

## 评分维度

| 维度 | 好方案信号 | 扣分信号 |
| --- | --- | --- |
| 业务背景 | 有具体客户场景、极端条件、传统模式失效点、关键角色和业务后果 | 只写行业趋势、平台定位、宏观痛点 |
| 预期效果 | 有可见结果，如时间压缩、风险提前发现、资源自动唤醒、画面变化、动作下发 | 只有“提升效率、辅助决策、智能化升级” |
| 演示故事 | 按时间线或决策链推进，冲突逐步升级，最后闭环消解 | 章节彼此孤立，客户看不到为什么要演示这几步 |
| 动态本体 | 有对象、静态属性、动态属性、规则/函数、外部交互对象 | 只有实体分类，没有状态变化和规则触发 |
| 数据需求 | 明确数据项、来源方、频率、治理加工、隐私脱敏、质量处理、算法支撑 | 只写“接入多源数据”“打通系统” |
| 决策机制 | 讲清事件、订阅、规则、沙箱推演、状态重写、动作执行、回写验证 | 系统像黑盒，所有结果都靠“AI 自动生成” |
| 可演示性 | 有可制作画面、步骤、输入数据、触发条件、输出动作和主持人口径 | 只有后台能力，缺少可视化和客户可感知动作 |
| 可信度 | 区分真实能力、演示替身、假设数据、接口前提、人工确认点 | 直接承诺生产接管、毫秒级控制或全自动闭环但无边界 |
| 图文表达 | 图承担业务流程、对象关系、决策树、模型层次或演示大屏 | 图只是装饰，或与正文逻辑不一致 |
| 文风 | 具体、克制、有业务细节，没有明显 AI 模板腔 | 形容词堆叠、概念重复、缺少数字和约束 |

## 从优秀材料萃取的模式

优秀的售前演示需求分析材料通常不是从“系统有什么模块”开始，而是按以下顺序组织：

1. 用真实高压场景开篇：例如大型赛事、突发天气、设施故障、资源挤兑、跨部门协同失效。
2. 对比传统模式：说明静态预案、人工调度、事后响应为何会失败。
3. 给出一句话目标：从被动应对变成提前推演、主动干预、自动重构。
4. 选择一个能打动客户的主场景：用时间线展现外部扰动如何引发连锁风险。
5. 把主场景拆成本体对象：角色、人群、空间、路网、运力、环境、异常事件等。
6. 给每类对象补齐静态属性、动态属性、规则函数、外部交互对象。
7. 把数据需求表格化：数据域、实体对象、核心数据项、来源方、更新频率、治理加工、算法/架构能力。
8. 用图片承接复杂逻辑：一张全景故事图、一张动态本体支撑图、若干对象卡片、一组决策路径图。
9. 用物理动作收束价值：导航重定向、诱导屏变化、调度单、信号方案、风险预警、报告输出等。
10. 用边界提升可信度：说明生产接入、权限、合规和安全动作是正式落地前提，演示可使用仿真或人工确认替代。

## 必须追问或现场取证的情况

- 用户要求判断“当前系统是否已经能演示”。
- 方案承诺生产系统接管、第三方平台 API、信号控制、调度派单、个人级数据使用。
- 方案含敏感数据、个人轨迹、身份证件、通信信令或公共安全系统。
- 指标看起来像拍脑袋，例如“100%”“毫秒级”“压缩 40%”“提前 24 小时”但没有说明假设或来源。
- 图片或文本引用了外部系统能力，但仓库或现场材料没有对应说明。

## 补强建议模板

写建议时使用“位置 + 动作 + 目标”：

- 在“业务背景”后补一段传统模式失效链路，说明客户为什么不能继续依赖人工预案。
- 在“本体模型”中为每个核心对象补静态属性、动态属性、规则函数和外部交互对象，避免本体沦为名词表。
- 在“数据需求”中新增表格，列出数据项、来源方、频率、治理加工和支撑算法，支撑演示可信度。
- 在“演示流程”中补时间线、触发条件、系统动作、可视化画面和最终输出，保证主持人能照着讲。
- 在“风险边界”中声明生产控制类动作采用仿真或人工确认，避免客户质疑权限和安全。

## 常见结论写法

- “这份材料已经接近可售前使用，优势是业务故事完整、本体和数据链条能互相支撑；主要风险是生产控制类动作边界需要补清。”
- “这份材料目前更像技术能力说明，不适合作为客户演示脚本；需要先重构为一个有冲突、有推演、有物理结果的业务故事。”
- “主线成立，但数据需求和演示画面还不够支撑客户信任；建议先补数据治理表和 3-5 个关键画面，再进入售前材料打磨。”
