# OSINT 数据查询与查证

## 目标

把用户的问题改写成可核验命题，选择最短的数据源组合，留下可复现查询记录，并明确证据能支持到哪一步。优先产出可审计判断，不以“查到很多结果”为完成标准。

## 开始前

1. 先确认任务是历史复盘、当前状态核验、数据源能力摸底，还是持续监测；时效性不同，查询策略不同。
2. 将自然语言拆成 `claim_id`：主体、动作或状态、事件时间、空间范围、需要证明的强度。
3. 校正数据类型。将 AIS/ADS-B 归为开放广播遥测或航迹观测；只有公开可访问或已获明确授权的信号线索才进入本流程。用户使用“SIGINT”表述会触发查询，但该词不改变访问权限和安全边界，也不把开放遥测误标为传统 SIGINT。
4. 遇到实时军事部署、精确坐标、武器发射点、打击目标或进攻性建议，收敛为历史、区域聚合、民用运行与风险防护口径；无法安全收敛时停止。
5. 涉及“当前”“最新”“是否仍然”或外部 API 行为时，必须现场查询；不要复用旧文档数字冒充当前结果。

- 查询新闻、海事、航空、遥感、网络或市场公开 API 时，读 [public-source-query-playbook.md](references/public-source-query-playbook.md)。
- 查询内部 AIS/ADS-B 或 195 环境航迹工作台 SQLite 数据时，必须读 [trajectory-query-playbook.md](references/trajectory-query-playbook.md)；只读 API 是该数据源的访问入口，不算另一数据源。

## 查询工作流

### 1. 冻结命题和判定条件

为每个命题写清：

- 直接确认需要什么证据；
- 哪些数据只能支持、反驳或提供背景；
- 哪些反向材料会推翻当前解释；
- 什么情况下只能写“未发现”，不能写“不存在”。

优先查最接近事件的原始来源，再补独立来源和结构化观测。参与方官方材料能直接确认“该方公开说了什么”，不能自动确认战果、归因或因果关系。

### 2. 建立最小查询路由

按命题选择 2—4 类互补证据，不机械全源扫描：

| 命题 | 首选 | 补强或反证 |
| --- | --- | --- |
| 谁发布了什么、事件何时公开 | 官方原文、机构通报、RSS | 独立通讯社、传播链去重 |
| 航空活动和支援结构 | 项目 ADS-B、ADSB.lol/OpenSky | NOTAM、机场/航司、METAR、同窗基线 |
| 船流和海事风险 | 项目 AIS、PortWatch、GFW | IMO、NAVAREA、港口、AISStream、SAR |
| 地表热异常或设施变化 | FIRMS | Sentinel-1/2、Landsat、官方/现场材料 |
| 网络中断 | IODA | RIPE Atlas、Cloudflare Radar（若已接入） |
| 冲突事件历史基线 | GDELT、已授权 ACLED/UCDP | 回到原始报道和官方材料 |
| 市场风险定价 | 分钟行情 | FRED/EIA 等日周频基线；不单独证明事件原因 |

### 3. 先做小样本能力探测

对陌生 API 或数据集先用一个短时间窗、小 AOI、单对象或一页数据验证：

- HTTP 状态和业务状态是否同时成功；
- 时间字段、时区、空间过滤、分页、排序和上限是否符合文档；
- 返回字段的类型、单位、空值和来源是否明确；
- 数据最新时间、覆盖范围和延迟如何；
- 零结果能否由对照区或已知样本区解释；
- 是否存在限流、动态分页、补录或修订。

未做真实小样本调用时，不把接口文档写成“已验证能力”。

### 4. 再做事件窗、前序窗和基线窗

- 内部统一使用 UTC 和半开区间 `[start, end)`，展示时再转换来源当地时间和 CST。
- 固定 AOI、对象去重规则、数据新鲜度阈值和地面/空中口径后再比较。
- 至少准备事件窗与前一日同钟点；需要判断异常时，优先补 14—28 天同星期同时段基线。
- 记录数、唯一对象数、有效对象数和连续航迹对象数分开统计。
- 事件后看到的对象必须回查事件前是否已存在，避免把“继续可见”误写成“事件后突然出现”。

### 5. 做质量门禁

按命题逐字段放行，不因一个坏字段丢弃整条记录，也不把坏字段降一点权重后继续参与派生：

- 身份、时间、位置、速度、航向、类别分别标记 validity；
- 检查时间倒置、入库延迟、坐标越界、重复、身份冲突、单位未知、点位稀疏和瞬时跳变；
- 单点只支持“该时刻被数据源看见”，不支持连续路线、停留、改道或因果；
- 同一对象的多点和同一通讯社的多站转载都属于同一信息家族，不重复增加独立性。

### 6. 合成命题级结论

使用 `直接确认 / 支持 / 反驳 / 背景 / 重复 / 未知` 标记证据作用。分别给出：

1. 已确认事实；
2. 基于证据的推测；
3. 当前不能验证的内容；
4. 覆盖、时效、许可和方法限制；
5. 下一条最有价值的补证动作。

不要把分析置信度写成事件发生概率，不输出没有校准依据的伪精确分数。

## 高效原则

1. 先查已有台账、派生层和最近查询结果，只为变化或缺口重查原始数据。
2. 新闻先追源链和去重，再扩关键词；结构化源先探测字段和覆盖，再扩大窗口。
3. 大规模结构化数据先查目录、字段画像和已有聚合结果，再按时间、空间和对象逐步缩小窗口，不反复全量扫描。
4. 航迹先按对象数和点数分布筛候选，再查对象级明细；先聚合后下钻。
5. 影像先查 STAC 目录、覆盖、云量和相近轨道，再下载目标窗口；不要先整景下载。
6. 负面结论必须附覆盖和可探测性；“没查到”通常只代表当前渠道未发现。
7. 保存原始响应摘要、查询参数、采集时间、HTTP/业务码、版本和 SHA-256；凭据、token、完整敏感点位不进入文档、日志或 Git。

## 输出要求

简短查询至少给出：命题、时点、查询源、查询参数摘要、结果、能证明什么、不能证明什么。

正式查证使用参考模板，至少包含：

- 结论时点和知识截止时间；
- 命题级证据矩阵；
- 查询窗口、AOI、字段和去重口径；
- 支持材料、反向材料、覆盖和数据缺口；
- 复现入口或命令（去除密钥和敏感信息）；
- 原始事实、派生指标、分析推断和模拟样例的分层标签。

用户未要求改系统时保持只读，不启动采集、历史回填、备份、索引、发布或跨仓代码修改。
