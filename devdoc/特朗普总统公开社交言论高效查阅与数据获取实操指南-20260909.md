# 特朗普总统公开社交言论高效查阅与数据获取实操指南

> 现场复核时间：2026 年 9 月 9 日。本文面向需要快速查清“特朗普在什么时间公开说过什么”的研究、情报分析和演示数据准备人员。

## 一、结论：最快、最稳的查询主线

在当前网络条件下，高效查阅特朗普 Truth Social 公开言论，不需要下载 172 GB 的完整多媒体数据，也不应只依赖一次关键词搜索。推荐使用四步主线：

1. 用 [Trump’s Truth 搜索页](https://www.trumpstruth.org/search)快速发现候选，利用它对正文、图片描述和视频转录的联合搜索能力提高召回率；
2. 用 [Trump’s Truth RSS](https://www.trumpstruth.org/feed)按 UTC 自然日抓取增量，避免长时间窗只返回最新 100 条而静默漏数；
3. 回到每条候选的详情页，确认正文、原帖时间、Truth Social ID、原始 URL 和帖子类型；
4. 需要批量历史分析时，下载 Cameronk199 数据集约 10.5 MB 的 `full_archive.posts.v1.jsonl.gz`，用系统已有的 `gzip + jq` 检索、过滤和去重；只有确需图片或视频内容时才读取对应媒体索引或分片。

这条主线把“发现、补全、核验、批量分析”分开。搜索命中只表示候选，不等于特朗普本人原创、相关主张或独立事实；最终结论必须回到详情记录和原始 Truth Social 身份。原始 URL 能访问时仍应核对 Truth Social 原帖；Trump’s Truth 和两个 Hugging Face 数据集都是独立归档或研究数据，不是特朗普、Truth Social 或美国政府的官方发布系统。

## 二、为什么这样组合

### 2.1 搜索页适合找候选，不适合直接计数

Trump’s Truth 的 [FAQ](https://www.trumpstruth.org/faq)说明，站内搜索不仅查正文，也查图片分析和视频转录；这比当前无法稳定访问的 Truth Social 原生页面更适合做主题发现。搜索页还可以包含已删除帖候选。

但搜索结果中可能混有：

- 原帖、引用帖和 ReTruth；
- 帖子正文、图片描述、视频转录和链接预览；
- 同一详情 URL 的重复搜索卡片；
- 只是在转发文章标题中出现关键词的帖子；
- 词干或子串造成的假阳性。

因此，搜索页的总数只能写成“搜索卡片数”或“原始命中数”，不能写成“相关言论数”。

### 2.2 RSS 适合增量抓取，但必须按日切片

RSS 返回结构化 XML，包含详情 URL、`guid`、UTC 发布时间、Truth Social 原始 URL 和原始 ID，适合持续增量采集。

本次现场验证发现：

- 查询 `2026-08-01` 至 `2026-09-09`，RSS 只返回最新 100 条，最早一条为 `2026-09-06T18:54:04Z`；
- 单独查询 `2026-08-01`，返回 45 条；
- 参数两端按自然日包含，`start_date=2026-08-01&end_date=2026-08-01` 只返回该 UTC 日期；
- 8 月 1 日 22:05 EDT 发布的帖子在 UTC 已是 8 月 2 日，因此只查 UTC 8 月 1 日会漏掉它。

所以，大时间窗不能一次拉完。历史抓取按 UTC 日循环；按美国东部当地日期研究时，先多取前后各一天，再转换时区精确过滤。

### 2.3 详情页负责身份核验，但 `Capture Date` 不是首次发现时间

详情页当前可以取得：

- 归档详情 ID，例如 `40453`；
- 正文；
- 原帖显示时间及 `EDT/EST` 时区；
- Truth Social 原帖 ID；
- Truth Social 原始 URL；
- 当前页面展示的 `Capture Date`；
- 页面是否标记为 ReTruth，以及可能嵌套的原帖内容。

其中 `Capture Date` 会随归档重新抓取而变化，不能直接解释为“第一次采集到该帖子”。同一条 `40453`：

- 2026 年 9 月 9 日访问详情页时，页面显示 `Capture Date = Tuesday, September 8, 2026, 10:22 am EDT`；
- 2026 年 8 月 31 日生成的冻结数据集中，同一记录的 `capture_date_utc = 2026-08-02T06:01:00Z`。

这证明详情页的 `Capture Date` 更接近当前归档记录的刷新时间。要回答“系统最早何时已经知道”，必须使用自己的首次采集台账、带版本的冻结快照或不可变原始响应，不能根据今天的详情页倒推。

### 2.4 历史快照只下载主文本表，不下载整个多媒体包

[Cameronk199/donald-trump-truth-social-posts](https://huggingface.co/datasets/Cameronk199/donald-trump-truth-social-posts)完整仓库约 172 GB，是因为同时包含图片、附件索引和其他派生表。大多数言论检索只需要：

- `data/full_archive.posts.v1.jsonl.gz`：10,542,827 字节，适合 `gzip + jq`；
- 或 `data/full_archive.posts.v1.parquet`：13,954,809 字节，适合 pandas、Polars 或 DuckDB。

当前冻结快照含 36,170 行和 36,170 个唯一 Truth Social ID，时间覆盖 `2022-02-14T15:54:00Z` 至 `2026-08-31T12:09:00Z`。它不是官方数据源，而是从 Trump’s Truth 详情页构建的独立研究快照；来源权利、平台条款和下游使用方式仍需单独核对。

## 三、第一步：用搜索页发现候选

### 3.1 先设计少量有效查询词

不要试图用一条长布尔表达式包办全部主题。先用主体或区域词召回，再用动作词缩小：

- 主体／区域：`Iran`、`Iranian`、`Hormuz`；
- 行动：`strike`、`attack`、`cancel`、`sanction`、`deal`、`negotiate`；
- 需要严格核对的原话：截取 4—8 个连续英文词做短语搜索。

`Iran` 一类宽词用于发现，不能直接用于统计。真正形成事件命题时，再把帖子拆成“谁、在什么时间、声称采取什么动作、是否带条件”。

### 3.2 单页查询命令

```bash
curl --noproxy '*' -sS --max-time 50 --get \
  'https://www.trumpstruth.org/search' \
  --data-urlencode 'query=Iran' \
  --data-urlencode 'start_date=2026-08-01' \
  --data-urlencode 'end_date=2026-09-09' \
  --data-urlencode 'sort=date_desc' \
  --data-urlencode 'removed=include' \
  --data-urlencode 'per_page=100' \
  --data-urlencode 'page=1' \
  -o search-page-1.html
```

`--noproxy '*'` 是本机当前网络环境下成功使用的直连方式；其他环境正常访问时可以去掉。`sort`、`removed`、`per_page` 和 `page` 是本次从页面行为实测可用的参数，不应当成永久不变的正式 API 合同。

先看总数和详情入口：

```bash
rg -n 'results|data-status-url=' search-page-1.html | sed -n '1,30p'
```

### 3.3 分页完整性检查

本次 `Iran + 2026-08-01～2026-09-09` 实测为 229 张搜索卡片，共三页：100、100、29。合并后三页只有 218 个唯一详情 URL，其中 11 个 URL 出现不止一次。

下面的命令复现卡片数、唯一 URL 和重复 URL 数：

```bash
for page in 1 2 3; do
  curl --noproxy '*' -sS --max-time 50 --get \
    'https://www.trumpstruth.org/search' \
    --data-urlencode 'query=Iran' \
    --data-urlencode 'start_date=2026-08-01' \
    --data-urlencode 'end_date=2026-09-09' \
    --data-urlencode 'sort=date_desc' \
    --data-urlencode 'removed=include' \
    --data-urlencode 'per_page=100' \
    --data-urlencode "page=$page"
done | perl -ne '
  $cards += () = /class="search-result"/g;
  while (/data-status-url="([^"]+)"/g) { $urls{$1}++ }
  END {
    $repeated = 0;
    for $url (keys %urls) { $repeated++ if $urls{$url} > 1 }
    print "cards=$cards unique_urls=" . scalar(keys %urls) .
          " repeated_urls=$repeated\n";
  }
'
```

本次输出：

```text
cards=229 unique_urls=218 repeated_urls=11
```

页数应根据当次总数重新计算。搜索页可能缓存或继续收录新帖，不能长期复用 229 或三页这个值。

## 四、第二步：用 RSS 按日补全

### 4.1 获取一个 UTC 自然日

```bash
curl --noproxy '*' -sS --max-time 50 --get \
  'https://www.trumpstruth.org/feed' \
  --data-urlencode 'start_date=2026-08-02' \
  --data-urlencode 'end_date=2026-08-02' \
  -o truth-2026-08-02.xml
```

快速确认条数和日期：

```bash
xmllint --xpath 'count(/rss/channel/item)' truth-2026-08-02.xml
xmllint --xpath 'string(/rss/channel/item[1]/pubDate)' truth-2026-08-02.xml
```

### 4.2 转成便于处理的 JSONL

以下脚本只使用 Python 标准库：

```bash
python3 - truth-2026-08-02.xml <<'PY'
import json
import sys
import xml.etree.ElementTree as ET

path = sys.argv[1]
root = ET.parse(path).getroot()
ns = {"truth": "https://truthsocial.com/ns"}

for item in root.findall("./channel/item"):
    row = {
        "title": item.findtext("title"),
        "description_html": item.findtext("description"),
        "archive_url": item.findtext("link"),
        "guid": item.findtext("guid"),
        "published_at_rfc822": item.findtext("pubDate"),
        "truth_url": item.findtext("truth:originalUrl", namespaces=ns),
        "truth_id": item.findtext("truth:originalId", namespaces=ns),
    }
    print(json.dumps(row, ensure_ascii=False))
PY
```

RSS 的一条记录实际可以得到：正文标题或占位标题、HTML 摘要、Trump’s Truth 详情 URL、`guid`、UTC 发布时间、Truth Social 原始 URL 和原始 ID。

### 4.3 时区处理

RSS `pubDate` 使用 UTC。详情页显示的是美国东部 `EDT/EST`。若问题是“8 月 1 日特朗普说了什么”，应至少拉取 UTC 7 月 31 日至 8 月 3 日，再把 `pubDate` 转成 `America/New_York` 后筛选当地 8 月 1 日。

本次已知帖子 `40453` 的详情页时间是 8 月 1 日 22:05 EDT，对应 `2026-08-02T02:05:00Z`。实测它在 RSS 的 UTC 8 月 2 日结果中出现，在 UTC 8 月 1 日结果中不出现。

## 五、第三步：回到详情页核验

### 5.1 下载详情页

```bash
curl --noproxy '*' -sS --max-time 50 \
  'https://www.trumpstruth.org/statuses/40453' \
  -o status-40453.html
```

### 5.2 用 macOS 自带 `xmllint` 提取关键字段

```bash
xmllint --html --xpath \
  'normalize-space(//div[contains(concat(" ",normalize-space(@class)," ")," status__content ")])' \
  status-40453.html 2>/dev/null

xmllint --html --xpath \
  'normalize-space(//td[normalize-space(.)="Original Post Date"]/following-sibling::td[1])' \
  status-40453.html 2>/dev/null

xmllint --html --xpath \
  'normalize-space(//td[normalize-space(.)="Capture Date"]/following-sibling::td[1])' \
  status-40453.html 2>/dev/null

xmllint --html --xpath \
  'normalize-space(//td[normalize-space(.)="TRUTH Social status ID"]/following-sibling::td[1])' \
  status-40453.html 2>/dev/null

xmllint --html --xpath \
  'string(//td[normalize-space(.)="Original URL"]/following-sibling::td[1]/a/@href)' \
  status-40453.html 2>/dev/null
```

本次实际得到：

```text
Original Post Date  Saturday, August 1, 2026, 10:05 pm EDT
Capture Date        Tuesday, September 8, 2026, 10:22 am EDT
Truth Social ID     117023461141824050
Original URL        https://truthsocial.com/@realDonaldTrump/117023461141824050
```

正文也可完整提取。保存时应另外记录自己的 `retrieved_at_utc` 和响应 SHA-256；不要把页面当前的 `Capture Date` 改名为 `first_seen_at`。

### 5.3 详情核验时必须回答的四个问题

1. 页面记录的是特朗普原创、引用还是 ReTruth？
2. 命中的词来自特朗普正文、被引用正文、图片描述、视频转录还是链接预览？
3. 原帖时间换算成 UTC 后落在哪个事件窗口？
4. 原始 Truth Social ID 和 URL 是否存在，能否作为跨来源去重键？

只有第 1、2 项确认后，才能表述“特朗普本人公开声称……”。转发文章标题中出现一句话，不能自动算作他的原创主张。

### 6.3 按时间、正文和媒体描述筛候选

下面的命令检索 2026 年 8 月中正文或附件描述出现完整单词 `Iran`、`Iranian`、`Hormuz` 的记录，并输出追源所需字段：

```bash
gzip -dc full_archive.posts.v1.jsonl.gz | jq -c '
select(
  .created_at_utc >= "2026-08-01T00:00:00Z"
  and .created_at_utc < "2026-09-01T00:00:00Z"
)
| select(
    ((.content_text // "") | test("\\b(Iran|Iranian|Hormuz)\\b"; "i"))
    or any(
      .attachments[]?;
      (.description_text // "") | test("\\b(Iran|Iranian|Hormuz)\\b"; "i")
    )
  )
| {
    trumpstruth_id,
    truth_id,
    created_at_utc,
    capture_date_utc,
    post_type,
    content_text,
    attachments,
    source_url,
    truth_url
  }
' > iran-candidates-2026-08.jsonl

wc -l iran-candidates-2026-08.jsonl
```

本次实测的筛选层级为：

| 层级 | 数量 | 含义 |
| --- | ---: | --- |
| 2026 年 8 月快照记录 | 333 | 当月全部帖子类型 |
| 正文命中三个词之一 | 20 | 不含只在媒体描述中的命中 |
| 正文或附件描述命中 | 26 | 高召回候选 |
| 上述候选中的原创帖 | 24 | 仍需逐条判断业务相关性和命题 |

这 24 条不能直接命名为“24 条伊朗相关政策言论”。它们只是按三个词、一个月和 `post_type=original` 得到的候选；链接标题、引用语境、否定表达和媒体描述仍需人工或规则复核。

### 6.5 Parquet 什么时候更合适

已有 pandas、Polars 或 DuckDB 时，Parquet 更适合反复聚合：

```python
import pandas as pd

posts = pd.read_parquet("data/full_archive.posts.v1.parquet")
posts["created_at_utc"] = pd.to_datetime(posts["created_at_utc"], utc=True)

candidates = posts[
    posts["created_at_utc"].between(
        "2026-08-01T00:00:00Z",
        "2026-09-01T00:00:00Z",
        inclusive="left",
    )
    & posts["content_text"].fillna("").str.contains(
        r"\b(Iran|Iranian|Hormuz)\b", case=False, regex=True
    )
]
```

只做一次筛选时，JSONL.gz 加 `jq` 已足够，不必为 36,170 行数据临时安装整套分析环境。

## 七、最终实际能获取什么数据

推荐把数据分成“来源原貌”和“规范化记录”两层。规范化记录至少包含：

| 字段 | 来自哪里 | 用途 |
| --- | --- | --- |
| `archive_status_id` | Trump’s Truth URL 或数据集 `trumpstruth_id` | 定位归档详情 |
| `truth_id` | RSS、详情页或数据集 | 跨入口去重的主键 |
| `truth_url` | RSS、详情页或数据集 | 回到 Truth Social 原帖 |
| `archive_url` | RSS、搜索页或数据集 `source_url` | 回到公开归档详情 |
| `created_at_utc` | RSS 转换、详情页转换或数据集 | 事件时间 |
| `display_time`、`display_timezone` | 详情页 | 保留来源显示口径 |
| `retrieved_at_utc` | 自己的采集程序 | 证明本系统何时取得 |
| `archive_capture_at` | 详情页或冻结快照 | 归档记录的采集／刷新信息，不冒充首次见到 |
| `post_type` | 详情页判断或数据集 | 区分原创、引用和 ReTruth |
| `content_text`、`content_html` | RSS、详情页或数据集 | 文本分析与原貌保留 |
| `attachments[].description_text` | 数据集或详情页 | 图片文字／描述候选 |
| `caption_tracks` | 数据集或详情页 | 视频转录入口 |
| `content_surface` | 自己归一化 | 标记命中来自正文、图片、视频还是链接预览 |
| `response_sha256` | 自己计算 | 固定本次取得的原始版本 |

一条可交付的规范化记录可以是：

```json
{
  "archive_status_id": "40453",
  "truth_id": "117023461141824050",
  "truth_url": "https://truthsocial.com/@realDonaldTrump/117023461141824050",
  "archive_url": "https://www.trumpstruth.org/statuses/40453",
  "created_at_utc": "2026-08-02T02:05:00Z",
  "post_type": "original",
  "content_surface": "body",
  "content_text": "...",
  "retrieved_at_utc": "<本次采集时间>",
  "response_sha256": "<本次原始响应哈希>"
}
```

能够可靠回答的是：

- 归档记录显示特朗普账号在什么时间发布或转发了什么公开内容；
- 原帖 ID、原始 URL、正文和可用媒体描述是什么；
- 哪些候选命中特定词、时间窗和帖子类型；
- 同一言论在不同冻结快照中何时已经出现。

不能仅凭这些数据回答的是：

- 帖子中的军事、外交、经济或战果主张是否属实；
- 一条 ReTruth 是否等同于特朗普原创表述；
- 搜索命中数是否等于独立言论数；
- 当前详情页的 `Capture Date` 是否等于首次采集时间；
- 帖子的真实曝光、传播效果或公众影响。Cameronk199 数据集明确不提供可信的点赞、回复、展示等传播指标。

## 八、两个数据集怎样选

| 数据源 | 最适合做什么 | 不应怎样使用 |
| --- | --- | --- |
| Trump’s Truth 搜索／RSS／详情 | 当前发现、日增量、原文和身份核验 | 不把搜索卡片数当言论数；不把归档站当美国政府官方来源 |
| Cameronk199 主帖子表 | 历史全文、时间线、帖子类型、媒体描述和可复现对账 | 不为文本分析下载 172 GB 全包；不把快照覆盖说成绝对完整 |
| Cameronk199 媒体索引／分片 | 只有命题依赖图片或视频时下钻 | 不在问题只需正文时下载全部媒体 |
| [chrissoria/trump-truth-social](https://huggingface.co/datasets/chrissoria/trump-truth-social) | 用五模型标签、市场和 GDELT 日度特征做候选排序或研究 | 模型标签和同日 GDELT 不能作为帖子主张的事实证明；`CC BY-NC 4.0` 许可不适合未经核对的商业使用 |

`chrissoria` 数据集适合回答“哪些帖子可能更值得先看”，不适合回答“特朗普到底说过什么”。其标签由模型生成，GDELT 是日粒度聚合，还可能包含帖子发布后的同日事件；如果直接拿来证明“发帖后发生了什么”，容易发生时间穿越。

## 九、合并、去重和质量规则

### 9.1 去重优先级

1. 优先使用 `truth_id`；
2. 缺失时使用规范化 `truth_url`；
3. 再退到 `archive_status_id`；
4. 文本 hash 只用于发现重复内容，不能替代身份 ID，因为特朗普可能重复发布相同文本。

搜索结果按详情 URL 去重后仍不等于独立主张。还要根据 `post_type` 区分原创／引用／ReTruth，根据 `content_surface` 区分正文／媒体／链接预览。

### 9.2 时间必须保留三条线

- `created_at_utc`：原帖发生时间；
- `retrieved_at_utc`：本系统取得时间；
- `archive_capture_at`：归档数据当时记录的抓取或刷新时间。

事件回溯以 `created_at_utc` 归属窗口；复盘“系统当时知道什么”使用自己的 `retrieved_at_utc`。两种问题不能共用一个时间字段。

### 9.3 内容来源必须可见

搜索命中后给每条候选标记：

- `body`：特朗普账号正文；
- `quoted_body`：被引用账号正文；
- `image_description`：图片识别或人工描述；
- `video_transcript`：视频转录；
- `link_preview`：外链标题或摘要。

只有 `body` 中的原创表述，才可以直接写成“特朗普本人发文称……”。其他表面需要说明转发、引用或媒体来源关系。

### 9.4 原始响应要留版本

每次正式采集至少保存：

- 查询 URL 和脱敏参数；
- 查询时间；
- HTTP 状态；
- 页数、卡片数和唯一 URL 数；
- 原始 HTML/XML/JSONL 的 SHA-256；
- 数据覆盖起止和最新时间；
- 解析脚本版本。

归档页面会更新，只有保存原始响应或冻结快照，后续才能解释同一字段为什么变化。

## 十、失败处理和停止条件

| 现象 | 正确处理 |
| --- | --- |
| RSS 恰好返回 100 条 | 视为可能截断，缩小到逐日窗口，不直接宣布完整 |
| 搜索卡片数大于唯一 URL 数 | 先按详情 URL 去重，再核验帖子类型和内容表面 |
| 当地日期与 RSS 日期对不上 | 转成 UTC；研究美国东部自然日时多取前后各一天 |
| 详情页 `Capture Date` 发生变化 | 将它视为归档刷新字段；首次发现时间回到自己的台账或冻结快照 |
| 标题是 `[No Title]` | 读取 `description`、详情正文和媒体描述，不把空标题当空帖子 |
| 页面无法访问 | 有限重试后记录失败；改用 RSS、冻结数据集或浏览器，不绕过访问控制 |
| 数据集主文件已过覆盖终点 | 用逐日 RSS 和详情页补增量，再按 `truth_id` 合并 |
| 只有模型分类命中 | 只作候选排序，回到原始帖子核验，不进入事实证据 |
| 已取得主题候选但不能判断政策含义 | 停止自动判真，拆成可核验命题并补官方通报、独立报道或结构化观测 |

查询达到以下条件即可收口：候选分页已完成、RSS 日期无截断、关键候选已回到详情页、原帖身份和帖子类型已确认、原始响应和时间版本已保留。后续事实核验属于多源分析，不再是“查阅公开社交言论”本身。

## 十一、推荐的最小交付物

一次正式查询至少交付三个文件：

```text
trump-public-statements-<case>/
├── raw/                 # 原始 HTML、XML 或数据集文件；受控保存
├── normalized.jsonl     # 按 truth_id 归一化后的帖子记录
└── query-manifest.json  # 查询参数、时间、覆盖、数量、SHA-256 和解析版本
```

对阅读者的摘要只需要回答：

1. 查询了什么时间和主题；
2. 原始命中多少、去重后多少、原创候选多少；
3. 最重要的原帖是什么，原始 ID 和 URL 在哪里；
4. 哪些命中来自图片、视频、引用或链接预览；
5. 当前覆盖和不能证明的内容是什么。

做到这五点，查询结果既足够快，也能经受后续复核，而不会把搜索引擎命中误写成政治人物已经确认的事实。
