## 1. 决策摘要

### 1.1 总体判断

课题在当前阶段仍然可行，但必须把建设策略从“先补齐生产架构”切换为：

> 真实公开事实打底，冻结样例保证稳定，模拟缺失外部环节，以 `gintbroker` 完成两条
> L1→L2→L3 可交互演示链，并对真实、派生、模拟和待建设能力逐项标识。

这种方式能够证明：

1. 课题的产品链路和技术架构可实现。
2. 现有多源地图、专题、实时数据和 AI 操作面可复用。
3. 数据、影像平台和模型具备明确的替换接口，而不是只能播放一段视频。
4. 演示结果有来源、有时间、有证据状态，不靠无法复核的“大模型结论”撑场。

这种方式不能证明：

- 已达到 PRD 中 90% 以上目标识别精度、99.9% 可用性等生产指标。
- 已经接通真实影像订购平台、商业数据源或客户内部系统。
- 当前所有地图数据都已进入统一、可审计的生产数据库。

汇报口径必须是“核心链路可行、关键接口已抽象、当前以公开数据和样例数据验证”，不能说成
“PRD 已全部实现”。

### 1.2 对本轮三项思路的判断

| 思路 | 判断 | 当前采用方式 | 必须守住的边界 |
| --- | --- | --- | --- |
| 基于公开可信材料自制真实数据或样例数据 | 可行，且是当前主路径 | 公开事实冻结为样例包；缺失字段可做可解释派生；缺失链路用模拟记录补齐 | 真实、派生、模拟必须分级标识；每条可回查来源和加工说明 |
| 暂缓真实卫星影像平台 | 可行，建议立即暂缓 | 使用 `demo_fixture` 影像适配器，展示任务状态、T0/T1/T2、标注结果和变化对象 | 页面持续显示“公开样例/模拟任务”；不得宣称真实下单或模型精度 |
| 基于 `gintbroker` 增强完成汇报 | 可行，且是最短路径 | 复用军事专题入口、地图、实时背景、专题 API 和右侧情报面板，只补通用 bundle、证据、回放和报告展示 | 不把未部署产品分支或 mock 数据说成当前运行能力 |
| 按现有两份重型海事计划完整实施 | 当前不合理 | 两计划降为研究参考；只提取已核验的事件、来源、字段和质量规则 | 汇报前不执行 T0-T15 全链，不建设完整 Topic Engine、数据平台或多仓治理 |

### 1.3 当前立即暂停的范围

以下事项都合理，但不应成为本轮领导演示的前置依赖：

- 真实卫星订购、商业影像采购和供应商认证。
- 真实像素级变化检测模型训练与精度验收。
- `moye-v4-product`、`doops-dev` 与 `gintbroker` 三仓联调。
- PostgreSQL/PostGIS、对象存储、全量审计和正式 RBAC 建设。
- 通用 Topic Engine v2 的完整状态机、历史回填和配置代际治理。
- 30/180/365 天真实趋势、全量 AIS/ADS-B 历史库。
- 同时把 5 月、6 月两个海事专题都做到客户交付级。

这些内容保留为课题后续路线，不从总体方案中删除，但不再阻塞近期汇报。

## 3. 先纠正“两个专题”和“PRD 两类场景”的关系

### 3.1 关键纠偏

当前两份复杂计划分别对应：

- 5 月商船安全事件：`event_case`。
- 6 月霍尔木兹风险窗口：`risk_window`。

它们都是既有“四场景材料”中的海事风险内容专题，文件名里的“场景 2”不是
`PRD-v6` 的“场景二：连续影像变化检测”。即使两个海事专题全部实现，也主要证明
PRD 场景一的多源触发、证据组织和风险报告能力，不能单独证明 PRD 场景二。

因此，近期汇报不再以“同时实现两个海事专题”为目标，而以“各跑通一条 PRD 主链”为目标。

### 3.2 推荐的两个主 Demo

| 汇报主链 | 推荐内容载体 | 为什么这样选 | 当前数据策略 |
| --- | --- | --- | --- |
| `PRD-S1` 多源触发 → 验证 → 报告 | 5 月商船安全事件 | 已有 UKMTO/JMIC 事件锚点、AIS/ADS-B 数据和证据时间线，最适合展示 L1→L2→L3 | 公开通告 + 冻结遥测摘要 + 模拟影像任务/识别结果 |
| `PRD-S2` 连续影像变化 → 研判 → 报告 | 关键能源/港口设施持续监测 | 与 PRD 场景二天然一致，可展示 AOI、T0/T1/T2、变化对象、阈值、报告和持续任务 | 公开设施资料 + 公开或模拟多时相影像 + 人工标注变化结果 |

6 月霍尔木兹风险窗口保留为：

- 场景一的备选事件或背景专题。
- 领导追问“是否可扩展到持续区域风险监测”时的扩展示例。
- 后续真实数据补强和第二个海事专题。

它不再是近期汇报必须实现的第二条主链。这样可以直接砍掉大量重复的数据扫描、规则、专题发布、
双专题兼容和跨仓 Gate，同时真正覆盖 PRD 的两个核心场景。

### 3.3 对现有 HTML Mock 的定位

[DYINT场景2双专题交互Mock.html](DYINT场景2双专题交互Mock.html) 已经验证了专题选择、地图、
证据、任务和回放的交互方向，但当前仍是“两个海事专题”信息架构。它可以继续作为通用视觉外壳，
不能作为 PRD 两类场景已对齐的最终设计稿。

进入 `gintbroker` 编码前，应做一次轻量调整：

1. 保留 5 月事件专题，显式标记 `PRD-S1`。
2. 将第二个主入口改成“关键设施持续监测”，显式标记 `PRD-S2`。
3. 增加 T0/T1/T2 影像、变化区域、模拟任务状态和 L3 报告画面。
4. 把 6 月风险窗口移到“更多样例/备选专题”，不删除其研究成果。

## 4. 当前“预警”和“佐证来源”的复用边界

### 4.1 当前真实语义

部署环境中的新闻预警仍主要是：新闻标题关键词风险计分、来源权重、VADER 情绪和可选预测市场
匹配后的展示。它不是有状态、有审核、有证据关系的正式 L1 事件。

当前“佐证来源”来自空间邻近新闻 cluster 内的 `articles`：

- 文章数不等于独立来源数。
- 同一机构或同一原始稿可能被重复计数。
- 空间相近不等于讨论同一事件或支持同一主张。
- 当前没有 `support/refute/context/duplicate` 证据立场。

因此，近期演示不能继续把系统自动聚类文章直接称为“多源佐证”。

### 4.2 近期最小修正

| 当前能力 | 近期处理 | 不做的重建设 |
| --- | --- | --- |
| 新闻预警卡 | 复用视觉外壳，改成 L1 线索卡；拆开严重性、可信度和工作流状态 | 不训练风险模型，不承诺概率校准 |
| “佐证来源” | 未人工/规则确认前统一改为“相关报道”；主 Demo 使用人工冻结的 Claim × Evidence 清单 | 不在汇报前建设完整语义聚类和传播链识别 |
| `correlation_engine` | 可作为一条候选信号，必须显示规则和数据时间 | 不把空间共址自动写成因果结论 |
| `correlate_entity()` | 可生成背景 evidence pack | 不把固定经验置信度当成最终结论 |
| `source_items` | 复用来源、时间、URL、hash 字段设计 | 不在近期扩成全量高频事实库 |
| 当前报告页 | 保留结构化报告样式 | 不再通过 URL query 传整份报告或证据 JSON；使用服务端 bundle/report ID |
| 地图定位 | 选中事件后保持目标点可见，详情用侧栏或留出 padding | 不为所有入口重构完整 selection controller |

主 Demo 的证据矩阵可以先由确定性 JSON 产生。每条重要结论至少绑定一条证据，并说明是支持、
反驳、上下文还是重复；LLM 只用于摘要措辞，不得新增无引用事实。

## 5. 样例数据策略：可以“自制”，但不能“伪装”

### 5.1 四类数据分级

| `data_class` | 定义 | 页面标签 | 示例 |
| --- | --- | --- | --- |
| `REAL_LIVE` | 演示时从当前接口读取的真实数据 | 实时公开数据 | 当前 news/GDELT/地图背景 |
| `REAL_FROZEN` | 从公开可信来源或已有合法数据冻结的事实 | 冻结真实样例 | UKMTO/JMIC 通告、公开设施信息、事件窗口遥测摘要 |
| `DERIVED_SAMPLE` | 从真实数据裁剪、聚合、脱敏、人工标注或补齐展示字段后的派生数据 | 真实数据派生 | AOI 日摘要、匿名轨迹、人工整理的证据关系 |
| `SIMULATED` | 为演示缺失接口、未来状态或模型结果而构造的数据 | 模拟任务/模拟结果 | 影像任务状态、T1 到达通知、目标检测框、推送记录 |

禁止用 `SAMPLE` 一个模糊标签覆盖全部情况。领导可以接受模拟，但不能接受事后才发现“所谓真实结果
其实是编的”。

### 5.2 每条样例的最小溯源字段

```text
record_id
scenario_id
data_class
source_name
source_url_or_reference
source_published_at
captured_at
as_of
visible_from
transform_note
license_or_display_note
content_sha256
display_label
```

`visible_from` 用于防止历史回放读取未来信息；`transform_note` 必须说明裁剪、聚合、插值、人工标注
或模拟规则。无法公开 URL 时至少保留来源名称、归档引用和 hash。

### 5.3 存储与磁盘边界

- 原始 AIS/ADS-B、Excel、PDF、公开影像原件继续留在原路径或外部磁盘，原地只读。
- `dy-inta` 只保存文档、manifest、小型 JSON/CSV 契约和必要的压缩预览，不复制大体量原始数据。
- `gintbroker` 只接收运行 Demo 必需的小型 bundle 和优化后的图片/缩略图。
- 每个 bundle 必须记录外部原始路径、来源 hash 和构建时间；原始文件离线时，已冻结 bundle 仍可演示。
- 仓库内资产预算在轻量实施计划 T0 固定，超预算素材放外部介质或对象存储，不临时塞进 Git。

### 5.4 推荐的最小演示包

```text
demo_packages/prd_v6_leadership/
  manifest.json
  prd_s1_maritime_event/
    bundle.json
    map.geojson
    report.json
  prd_s2_facility_monitoring/
    bundle.json
    changes.geojson
    report.json
  assets/
    optimized-demo-images-only/
```

不再为每个专题建立十余个 CSV 子目录。源数据治理表可以在外部工作区生成，进入演示仓的只有页面
真正读取且能校验的少量契约文件。

## 6. 暂缓影像平台后的可信替代方案

### 6.1 演示适配器

保留一个最小 `ImageryTask` 契约，当前 provider 固定为 `demo_fixture`：

```text
task_id
scenario_id
aoi
requested_at
sensor_type
time_window
provider = demo_fixture
status = requested|scheduled|acquired|processed|failed
asset_ids[]
simulation_note
```

场景一演示：分析师确认 L1 后创建任务，时间轴自动推进到 `acquired` 和 `processed`，返回一张公开
样例或模拟影像及人工标注目标结果。

场景二演示：直接加载 T0/T1/T2 三期素材，生成变化区域、变化类型、置信区间或质量等级，并达到
阈值后生成 L1 变化预警和 L2 研判结果。

### 6.2 页面必须明确展示

- `模拟影像任务` 或 `公开样例影像` 徽标。
- 任务时间线与 provider。
- 每张影像的来源/许可或模拟说明。
- 标注结果是“人工预置”“规则生成”还是“模型输出”。
- “真实影像平台接入后将由同一接口替换”的后续说明。

### 6.3 当前不做

- 不配置 Sentinel/CDSE 凭据。
- 不接商业影像供应商。
- 不真实下发采集或补采任务。
- 不用预置结果宣称已经达到 PRD 的模型精度。
- 不因影像平台暂缓而删除 `ImageryTask`、`ImageryAsset` 和变化对象的产品概念。

这样既承认资源限制，又能证明课题链路不是纯 PPT。

## 7. `gintbroker` 近期只做哪些增强

### 7.1 必须完成

1. **通用专题选择**
   - 军事专题入口能加载多个 topic，不再只对 HIMARS、南海或美伊写死分支。
   - 当前只需支持两个汇报主 topic 和 HIMARS 回归。

2. **冻结 bundle 接口**
   - 建议新增 `GET /api/topics/{topic_id}/bundle`。
   - 直接校验并返回仓库内小型 JSON/GeoJSON，不引入新数据库。
   - 报告正文由 bundle 或 `report_id` 服务端读取，不放进 URL query。

3. **一个共享专题页面**
   - 左侧：专题与图层选择。
   - 中间：AOI、事件/设施、轨迹摘要、影像/变化图层和时间回放。
   - 右侧：当前判断、证据矩阵、影像任务/监测任务和 L3 报告。
   - 5 月事件与设施监测只通过 `topic_kind`/profile 改变内容，不复制整页组件。

4. **确定性回放**
   - 页面按 bundle 的 `as_of` 和时间点重放。
   - 断网、LiveUAMap 红灯或 AIS key 缺失时仍能完整演示。
   - 提供“一键重置到开场状态”。

5. **数据真伪标识**
   - 所有证据、影像任务、检测结果和报告都显示 `data_class`。
   - 客户/领导视图可隐藏技术 ID，但不能隐藏“模拟”性质。

6. **最低验证**
   - bundle schema test。
   - HIMARS 兼容 smoke。
   - 两个主 topic 打开、切换、回放、查看证据和报告的浏览器测试。
   - 目标环境截图或录屏作为现场降级资产。

### 7.2 推荐 bundle 形态

```json
{
  "topic_id": "dyint_prd_s1_maritime_event",
  "topic_kind": "event_case",
  "prd_scenario": "PRD-S1",
  "title": "商船安全事件多源验证",
  "as_of": "2026-05-28T00:00:00Z",
  "data_mode": "frozen_demo",
  "layers": [],
  "timeline": [],
  "claims": [],
  "evidence": [],
  "tasks": [],
  "imagery_assets": [],
  "changes": [],
  "report": {}
}
```

这一契约足够支撑汇报。正式的 `IntelEvent`、`EvidenceItem`、`AnalysisRun`、数据库状态机和审计表
放到后续生产化阶段，不在近期 Demo 内一次建完。

### 7.3 可选增强

- 叠加当前实时 news/GDELT/ships 作为“实时背景”，但不能影响主链。
- 报告打印样式或浏览器打印 PDF。
- 关键步骤的主持人提示和自动播放模式。
- 一个“能力边界”弹窗，展示真实、派生、模拟和后续接入项。

### 7.4 当前明确不做

- 不整体合并 `origin/chanpin@c55bff8`；只抽取视觉和交互模式，避免把南海 mock 与硬编码带入 main。
- 不实施美伊/南海 Topic Engine v2 的全量表、回填、generation、权限和控制面。
- 不修改 `doops-dev`、`moye-v4-product`。
- 不接真实外部认证源，不改生产凭据。
- 不做通用 LLM 情报推理平台。

| 0～1 分钟 | `gintbroker` 多源地图与军事专题入口 | 已有实时态势和可交互系统基础，不是从零做课题 |

## 9. 极简实施工作包

后续若转成实施计划，只保留四个工作包和三个 Gate，不再拆成 T0～T15。

| 工作包 | 主要任务 | 完成条件 | 可裁剪项 |
| --- | --- | --- | --- |
| W0 内容冻结 | 冻结 1 个海事事件、1 个设施对象、主持人口径和能力边界 | 两条故事均能映射 PRD，来源与模拟项清楚 | 6 月风险窗口退出主链 |
| W1 样例包 | 生成两个 bundle、manifest、压缩素材和报告 JSON | 离线可加载、schema 通过、每条关键结论可追溯 | 不做通用构建平台 |
| W2 系统接入 | 通用 topic bundle API、共享专题页面、回放、证据和报告 | 本地浏览器跑通两条链，HIMARS 不回归 | 不做数据库与真实外部任务 |
| W3 彩排发布 | 目标环境部署、8～12 分钟脚本、截图/录屏兜底 | 断外部源仍可演示；主持人能解释所有模拟边界 | PDF 可降级为 HTML/打印 |

三个 Gate：

- `G1 STORY_FROZEN`：主事件、设施对象和模拟口径冻结。
- `G2 LOCAL_DEMO_READY`：两条链在本地真实系统中可交互走通。
- `G3 LEADERSHIP_DEMO_READY`：目标环境回归、脚本彩排和降级资产完成。

粗略工作量仅作排期参考：熟悉现有项目的全栈开发与内容整理合计约 4～8 个有效人日；若前后端、
数据整理可并行，日历时间可进一步压缩。T0 现场探测后再承诺具体日期。

时间进一步压缩时，按以下顺序裁剪：

1. 先砍 6 月备选专题。
2. 再砍实时背景叠加。
3. 再把 PDF 降级为 HTML 报告。
4. 再把自动播放降级为主持人手动点击。

不得裁剪：来源追溯、模拟标识、两条 PRD 主链、确定性回放和降级截图。

## 10. 领导演示验收口径

### 10.1 必须通过

- 从军事专题入口能分别进入 `PRD-S1`、`PRD-S2`。
- 两条链都能看到 L1、L2、L3，不需要真实外部接口临场返回。
- 每条关键证据有来源、时间、数据类别和支持/反驳/上下文状态。
- 模拟影像任务和模拟检测结果在所有可见页面明确标识。
- 历史时间点不读取后验信息。
- 报告中的关键结论能反查证据，且包含信息缺口和能力边界。
- 外部网络或非核心源失败后，刷新页面仍能恢复固定演示。
- 有目标环境截图/录屏和静态报告作为现场兜底。

### 10.2 不作为近期验收项

- PRD 标称识别精度、定位精度和置信度区间。
- 真实卫星下单、补采、计费和供应商 SLA。
- 生产级并发、72 小时稳定性和 99.9% 可用性。
- 全角色 RBAC、不可篡改审计和正式数据归档。
- 全部四个业务场景或全部军事专题。

这些指标在汇报中作为后续研究验证计划展示，而不是伪造测试结果。

## 11. 风险、防护与回滚

| 风险 | 影响 | 防护 | 回滚/降级 |
| --- | --- | --- | --- |
| 样例数据被质疑为造假 | 课题可信度受损 | 四类数据分级、逐条来源和加工说明、页面模拟徽标 | 切换到证据附录，现场展示来源 manifest |
| 两个海事专题未覆盖 PRD 场景二 | 汇报证明力不足 | 主链改为海事事件 + 设施持续监测 | 6 月专题降为备选，不占主流程 |
| 目标环境外部源不稳定 | 演示中断 | 主链只读冻结 bundle，实时层为可选背景 | 使用本地缓存、截图或录屏 |
| `origin/chanpin` 与 main 冲突 | 合并周期失控 | 不整体合并产品分支，只抽取页面模式；最小改动落 current main 基线 | 关闭新入口，HIMARS 和全球态势保持原状 |
| 预警/佐证语义过度包装 | 领导追问时站不住 | “相关报道”和人工冻结证据分开；证据立场明确 | 降级为线索和待核验，不给确定性判断 |
| 模拟影像被误解为真实平台 | 形成错误承诺 | provider、状态和页面持续标记 `demo_fixture` | 隐藏模拟结果，只演示任务契约和公开素材 |
| 报告泄露或不可复现 | 证据与页面不一致 | 服务端 bundle/report ID、固定 `as_of` 和 hash | 回退静态只读报告，不用 URL query 传正文 |

## 13. 最终推荐

近期只做“一套系统、两个 PRD 主 Demo、一个共享页面、两个冻结 bundle”：

1. 以 5 月商船事件证明 PRD 场景一的多源触发、影像验证和融合报告链。
2. 以关键设施 T0/T1/T2 证明 PRD 场景二的持续监测、变化检测和变化报告链。
3. 两条链都复用 `gintbroker` 军事专题、地图、详情、回放和报告外壳。
4. 公开真实数据负责“站得住”，冻结 bundle 负责“演示稳”，模拟适配器负责“补齐尚未采购的外部能力”。
5. 领导汇报通过后，再根据反馈决定优先接真实影像平台、扩充数据源，还是推进 Topic Engine 和数据治理。

这条路线比同时实施两个重型海事专题更短，也更直接地证明 `PRD-v6` 的完整可行性。
