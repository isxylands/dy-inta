## 1. Gate 与一句话结论

方案已经具备进入实施阶段的条件。上一轮 P1“本地凭据代理缺少 Host/Origin 边界”和 P2“complete 缺少聚合响应字节上限”均已实质关闭：前者落实为最外层 guard、回环 allowlist、唯一 `PUBLIC_ORIGIN`、非回环 fail closed 和零上游调用测试；后者落实为单片、唯一记录数、逐记录聚合字节和最终完整 DTO 四层约束。重新建立目标覆盖矩阵后没有新的首期 gap，也没有因整改引入自有认证、CSRF 状态机或特殊治理协议。

`PASS` 表示方案的目标、技术路径、验证、失败恢复和执行入口成立，可以从 T0 开始；不表示目标实现仓已经创建，也不表示 T0～T4 的构建、浏览器或真实 API 证据已经通过。

## 2. 审查范围和关键事实

本轮重新读取了最新源方案、当前 sibling 评审报告、`f75fe5d` 相对上一轮评审基线的 Git delta、接口实测指南和交互 Mock，并走读首次建仓、恶意网页访问、空 token、多切片聚合、冷构建、真实 HTTP 验收和后续持久化入口。

关键事实：

1. 目标实现路径 `/Users/liushen/Documents/githubDevs/dy-track-explorer` 当前仍不存在，T0 可以按“路径不存在或为空”分支建立独立本地 Git 仓；远端、CI 和发布权限不再阻断本地 T0～T3。
2. 接口实测仍支持方案的核心判断：未登录可能 HTTP 200、业务 `604`；单页上限 1000；历史分页会重复或变化；`id` 只确认本轮样本内唯一；`endLoadTime` 有效但时区未确认。
3. 工具持有真实上游凭据并返回原始航迹响应。最新方案把 Host guard 放在静态资源、健康检查和 API handler 之前，并对 `/api/v1` 的非空 Origin 做精确匹配；非法来源在进入上游 client 前拒绝。
4. 非回环监听必须显式配置唯一 `PUBLIC_ORIGIN`，否则启动失败；后端不信任 `Forwarded` 或 `X-Forwarded-*` 扩展信任。多人访问仍须由现有 OIDC/SSO 或反向代理认证承担，不自建账号系统。
5. `complete` 的探测片不进入合并结果；接受记录前累计 JSON 字节，最终 DTO 在写 header/status 前再次受限编码，超限统一返回 `COMPLETE_RESULT_TOO_LARGE` 且不泄露部分 content。
6. `direct` 与 `complete` 保持互斥契约：前者保留一次上游原文，后者返回本地合并结果与切片摘要；后者永久标记 `best_effort`，任一必要切片失败即 fail-fast。
7. Go 1.26、React 19.2、Vite 8.1、Node 24 LTS、Ant Design 6.5 和 React Router 8.3 的版本口径与当前官方资料一致；准确 patch 版本仍由 T0 写入锁文件。
8. 方案没有 authorization/adoption/checksum/CAS、跨仓原子提交或其他特殊 Git 协议。五个首期阶段与 M1 Gate 均对应独立失败模式，复杂度与任务风险匹配。

## 4. 应保留的设计

1. 保留独立本地实现仓和远端/CI/发布后置，不重新引入外部写权限作为本地实施门禁。
2. 保留 Go 模块化单体、React SPA、单端口同源服务、dataset allowlist 和 Go-only secret 边界。
3. 保留薄 Host/Origin guard；不扩大成自有用户系统、CSRF 状态机或任意代理信任框架。
4. 保留 `Proxy=nil`、insecure 显式开关和 T4 单次风险确认；不新增本项目无法负责的 TLS/VPN 改造。
5. 保留 `direct`/`complete` 互斥响应、complete fail-fast、完整响应字节上限、永久 `best_effort` 和历史可变警告。
6. 保留 direct 8/14 位、complete 14 位的明确时间合同，以及 fake、race、Playwright、冷启动和低频真实 smoke 的分层验证。
7. 保留长期 `source_id`、SQLite/NFS、数据许可和时区为 M1 Gate，不提前创建空存储模块或唯一约束。

## 6. 最小执行路径和验证

1. T0 先做固定目标路径和 Git 根检查，再建立最小工程、OpenAPI、fake upstream 与 Host/Origin guard；guard 负向测试失败时不得进入 T1。
2. T1 实现认证、`Proxy=nil`、direct/complete、容量限制和错误语义；`go test -race ./...`、`go vet ./...` 及 OpenAPI 生成无漂移必须通过。
3. T2 只按已冻结契约实现探索工作台；Playwright 覆盖 ADS-B/AIS、604、切片失败、聚合超限、永久警告和窄屏。
4. T3 从无旧 `dist` 的工作树完成冷构建、单二进制和本地镜像验证；没有 Docker 时明确记录镜像项未验证，不伪造通过。
5. T4 只有在确认人、时间、适用网络和有效期齐全时才使用真实凭据；仅做低频、小范围、只读 smoke，并以 query_id 和脱敏摘要留证。

任一阶段失败只回退实现仓对应阶段提交；不修改 `dy-inta` 的业务材料，不用扩大真实请求范围代替定位。多人访问、外部 push/CI、制品发布和 M1 持久化仍按各自 Gate 单独取得条件。
