# DYINT 多源情报研判驱动的自演化本体模型方案

日期：2026-07-31
用途：多源情报验证、分析研判、预警、预测和行动建议的本体建设依据

## 一、结论

DYINT 所需本体应直接承载情报工作的判断和处置过程。对象、属性和关系用于描述世界；主张、观测、证据、假设、评估、预测、预警、任务和动作则记录系统如何认识世界、为什么改变判断、准备采取什么措施。两类内容缺一不可。

两篇钉钉文档说明，研判质量主要取决于以下能力：

- 将一篇报道拆成可核实的主张，分别检查事实、机制、影响和未来走势；
- 追到原始稿源和采集方法，避免把转载数量当成独立确认；
- 分开记录来源公开说了什么、现实中观测到什么、分析人员据此判断什么；
- 让支持材料、反向材料、覆盖空窗和关键缺口共同进入判断；
- 保留竞争性解释，允许新信息撤回旧结论；
- 将预警和建议绑定到对象、依据、有效期、升级条件和撤销条件；
- 用历史回放和实际结果校准规则、预测和来源评价。

因此，目标模型应采用“事实与对象、认知与证据、分析与预测、预警与动作、学习与治理”五个相互连接的模型域。它同时保存不可变的历史记录和当前有效投影。大模型负责提取候选、发现缺口、提出假设和变更建议；规则执行器负责确定性判断；分析人员负责高影响结论、规则发布和对外行动。

“自动演化”有三种含义，必须分开：

1. **态势演化**：新观测进入后，事件、判断、预测和建议持续更新。
2. **模型演化**：增加概念、关系、约束、规则和动作模板，并形成新版本。
3. **能力进化**：经过留出样本、历史回放和影子运行证明，新版本在误报、漏报、时效、概率校准或决策效用上优于旧版本。

前两项可以高度自动化。第三项必须以量化结果为依据，不能用“模型自己改了自己”代替效果证明。

## 二、材料中的业务方法

### 1. 研判对象从新闻退回到命题

入口报道只负责提供线索。分析任务需要把标题和正文拆成若干命题，例如“某方暂停行动”“另一方对等暂停”“暂停具有外交目的”“通航风险下降”。这些命题的证明条件不同，不能共用一个总置信度。

更合适的分层是：

| 主张层次 | 回答的问题 | 主要材料 | 典型错误 |
| --- | --- | --- | --- |
| 事实 | 谁在何时何地做了什么 | 当事方原始声明、独立现场材料、传感器观测 | 用标题或参与方说法确认整起事件 |
| 机制 | 为什么发生，事件之间是否有因果关系 | 原始政策表述、时间链、指挥或回应说明 | 因时间接近就建立因果关系 |
| 影响 | 航运、航空、设施、市场和民用服务发生了什么变化 | 连续运行数据、权威通告、业务指标、前后对照 | 用影响指标反向证明事件事实 |
| 预测 | 未来一定时间内最可能怎样发展 | 当前状态、领先指标、竞争性解释、历史校准 | 把分析置信度写成发生概率 |

本体必须把这四层显式建模。否则市场变化、遥感热点、官方声明和新闻转载都会混在同一个“事件证据”集合里，规则无法判断每项材料究竟能证明什么。

### 2. 多源的核心是独立性和互补性

媒体名称不同，稿源可能相同；多颗卫星的过境时间不同，传感器和算法可能属于同一方法家族。来源独立性应按原始采访、原始通报、采集链和检测方法分组，不按 URL 数量计算。

不同数据承担不同作用：

- 官方发布确认某个主体的公开立场和自述行动；
- 新闻采访发现变化并补充现场信息；
- AIS、ADS-B、遥感、网络和行情提供可观测变化；
- 历史数据说明常态和异常幅度；
- 业务台账、制裁清单和运行通告说明实际影响。

材料能否互相补强，取决于它们是否指向同一命题、时间、空间和对象。它们不能简单相加。

### 3. “未发现”也需要证据模型

没有检索到报道、接口返回零条、卫星没有检出热点，分量完全不同。负面结果只有同时记录观测覆盖、在线率、时延、目标可探测性和漏检条件，才能进入判断。

因此，“未发现”不作为一个普通布尔值保存，而应形成一项覆盖评估：查了什么、查到何时、若目标真实存在是否应当被看到、哪些条件会造成漏检。覆盖不足时，系统生成数据缺口或补采任务，不生成“事件不存在”的结论。

### 4. 新信息应改变结论和动作

第二篇文档的核心价值是连续重判：早期材料支持短暂停顿，新导弹事件出现后撤回“暂停仍在延续”，24 小时复核又保留“尚未确认连续直接互攻”。同一事件还被拆成发射方、来向、所宣称目标、拦截、落点和损害等字段分别确认。

这要求本体保存每一版判断及其知识截点。当前页面可以展示最新结论，历史版本不能被覆盖。新材料进入后，系统应说明：新增了什么、哪项主张改变、置信度为何变化、哪条建议随之升级或撤销。

### 5. 建议是有条件的决策对象

行动建议至少包含五项内容：接收对象、建议动作、判断依据、适用时间和调整条件。它还应记录误判代价、所需授权、执行状态和实际结果。

风险处置不只由事实置信度决定。某项高影响风险即使尚未确认，也可能值得加强监测；低影响且代价高的措施则需要更高的触发门槛。本体要把事实判断、风险评估和动作政策分开，避免“置信度达到 0.8 就自动发布高风险建议”这类简单联动。

## 三、目标和覆盖表

本方案以“系统能稳定辅助分析人员形成可复核、可更新、可执行的研判”为目标，不承诺当前平台已经实现全部能力，也不把大模型输出视为权威事实。

| 核心问题或成功指标 | 材料中的依据 | 模型措施 | 验证方式 | 状态 |
| --- | --- | --- | --- | --- |
| 新闻能够拆成可证伪主张 | 两篇文档均按主张逐项核验 | `Proposition`、`Claim` 和主张分层 | 任一关键结论可回到原子命题和成立条件 | covered |
| 转载和同方法数据不重复计数 | 文档按稿源和传感方法家族归并 | 来源依赖图、`IndependenceGroup` | 相同稿源或方法家族只形成一个独立组 | covered |
| 事实、机制、影响和预测不混用 | 评审材料已指出四层主张使用不同逻辑 | 分层命题、分型评估和规则范围 | 影响数据不能直接升级事实命题 | covered |
| “未发现”有明确分量 | 海事、遥感、网络和接口空结果均依赖覆盖解释 | `CoverageAssessment`、`NegativeFinding` | 所有负面结论带覆盖、时延和漏检条件 | covered |
| 新证据能够撤回旧判断 | 后续导弹事件改变了暂停判断 | 双时间、不可变评估版本、`supersedes` | 可重放任一知识截点并解释差异 | covered |
| 预测与分析置信度分开 | 文档明确两者含义不同 | `Forecast` 与 `AnalyticAssessment` 分离 | 概率、置信度及其依据分别展示 | covered |
| 预警和建议能直接服务业务 | 建议已按对象、依据和调整条件组织 | `Alert`、`Recommendation`、`ActionPolicy`、`Outcome` | 每条建议均有触发和撤销条件 | covered |
| AI 能持续提出模型改进 | 用户要求模型自动演化和进化 | 候选变更、回放、影子运行、审批和版本发布 | 未经评测和审批的变更不能进入生产 | covered |
| 进化效果可以证明 | 单案例尚不能证明稳定自动研判 | 留出集、历史回放、在线指标和回滚 | 新版本在预定指标上优于旧版 | covered |
| 与现有三类系统职责相容 | 本仓已明确数据、语义和实时运行面分工 | 高频原始数据留在数据/运行面，本体保存语义投影 | 合同测试、影子对账、热路径压测 | covered |

## 四、总体模型

```mermaid
flowchart LR
  S["来源材料和传感器观测"] --> P["命题、主张和观测"]
  P --> E["证据关系和覆盖评估"]
  E --> H["事件、假设和分析评估"]
  H --> F["预测、风险和预警"]
  F --> A["建议、任务和受控动作"]
  A --> O["执行结果和实际结局"]
  O --> L["规则评估和模型变更建议"]
  L -->|"回放、影子运行、审批"| R["新本体、规则和政策版本"]
  R --> P
```

模型分为五个域：

| 模型域 | 主要内容 | 解决的问题 |
| --- | --- | --- |
| 事实与对象 | 人、组织、船舶、航空器、设施、区域、服务、事件和观测对象 | 世界中有哪些对象，发生了哪些活动 |
| 认知与证据 | 来源材料、命题、主张、观测、证据关系、来源依赖和覆盖评估 | 当前知道什么，依据来自哪里，材料能证明到什么程度 |
| 分析与预测 | 假设、分析评估、风险评估、情景和预测 | 哪一种解释更符合材料，未来可能怎样变化 |
| 预警与动作 | 预警、核验任务、建议、动作政策、执行记录和报告 | 谁需要做什么，何时升级、撤销或复核 |
| 学习与治理 | 结果标签、规则表现、模型变更建议、评测、版本和发布记录 | 规则和本体为什么变化，新版本是否真正更好 |

这五个域是一个逻辑模型，不要求所有数据都放入同一种数据库。新闻正文、影像、视频和高频轨迹保存在数据平台或对象存储；本体保存稳定对象、命题、语义关系、摘要、引用、规则结果和版本。

## 五、核心概念

### 1. 任务和决策

| 对象 | 作用 | 关键语义 |
| --- | --- | --- |
| `IntelCase` 情报任务 | 组织一次连续研判 | 决策范围、时间窗、知识截点、负责人、当前版本 |
| `DecisionQuestion` 决策问题 | 说明谁需要据此决定什么 | 决策对象、最晚时限、误升与误降代价、停止条件 |
| `CollectionPlan` 采集计划 | 将关键未知项转为有边界的取证任务 | 待查命题、数据源、优先级、覆盖要求、截止时间 |

任务入口必须先固定决策问题。没有决策对象、时间要求和错误代价，检索范围会不断扩大，预警阈值和停止条件也无从确定。

### 2. 来源、命题和观测

| 对象 | 作用 | 不能与什么合并 |
| --- | --- | --- |
| `SourceArtifact` 来源材料 | 保存网页、通告、数据响应、影像及其快照引用 | 不等于材料中的事实主张 |
| `SourceActor` 信息主体 | 记录发布者、采访者、当事方、传感器或处理机构 | 不用一个全局分数概括其所有信息质量 |
| `Proposition` 命题 | 表达可判真伪的最小语义单元 | 不与整篇文章或整起事件等同 |
| `Claim` 主张 | 记录某主体在某材料中对某命题作出的陈述 | 不因来源权威而自动成为事实 |
| `Observation` 观测 | 保存传感器、统计或人工判读在给定方法和覆盖下得到的结果 | 不自动解释事件原因 |
| `DerivedFinding` 派生结果 | 保存基线、异常检测、轨迹和影像算法的计算结果 | 必须保留输入、算法和版本 |

`Proposition` 建议采用带限定项的原子表达：

```text
主体 + 谓词 + 客体或值
+ 事件时间 + 空间范围 + 条件 + 数量/单位 + 否定标记
```

例如“伊方恢复了针对美军目标的直接行动”需要继续拆成发射方、行动类型、所宣称目标、实际落点、拦截和损害等命题。每个字段可以由不同材料支持，不能用一个事件级置信度覆盖全部字段。

### 3. 证据和覆盖

| 对象 | 作用 | 关键字段 |
| --- | --- | --- |
| `EvidenceLink` 证据关系 | 将主张、观测或派生结果连接到命题或假设 | `role`、直接性、时间/空间一致性、说明 |
| `IndependenceGroup` 独立信息组 | 归并共同稿源、共同原始通报或同方法家族 | 原始来源、采集链、方法家族、依赖边 |
| `SourceAssessment` 来源评价 | 评价来源对特定信息类型的接近程度、稳定性和利益偏差 | 适用信息类型、时间范围、评价依据 |
| `InformationAssessment` 信息评价 | 评价某条具体材料是否可观测、完整、一致以及是否存在反证 | 可信等级、缺失字段、冲突项 |
| `CoverageAssessment` 覆盖评估 | 说明观测时空范围、在线率、延迟、可探测性和盲区 | 空间、时间、对象、方法、漏检条件 |
| `NegativeFinding` 负面发现 | 记录在合格覆盖内没有观察到预期信号 | 目标信号、预期可见性、实际结果、结论边界 |

`EvidenceLink.role` 至少包括：直接支持、间接支持、反驳、背景、重复、未知。关系目标必须是具体命题或假设，不能笼统写成“支持某事件”。

来源评价使用“来源 × 信息类型 × 时间范围”的局部模型。官方通讯社可以可靠证明“该方公开发布了什么”，并不因此可靠证明战果、损害或对手意图。数值评分只有经过历史校准后才进入决策规则；早期使用分级标签和文字依据更稳妥。

### 4. 事件、状态和分析

| 对象 | 作用 | 关键语义 |
| --- | --- | --- |
| `Event` 事件 | 聚合同一时空和业务语境下的对象、活动与命题 | 事件身份、参与者、时间、地点、组成事件 |
| `EventProjection` 事件投影 | 面向应用给出当前有效视图 | 知识截点、字段级确认状态、数据新鲜度 |
| `Hypothesis` 假设 | 表达对原因、机制或未来路径的竞争性解释 | 预期信号、反证、区分性指标、关键假设 |
| `AnalyticAssessment` 分析评估 | 记录分析人员或已批准规则对命题、事件或假设的判断 | 判断、分析置信度、依据、限制、有效期 |
| `RiskAssessment` 风险评估 | 将发生可能性、影响和处置代价转成业务风险 | 受影响对象、严重性、时间范围、误判代价 |
| `Forecast` 预测 | 记录未来某时限内的可检验判断 | 预测目标、期限、概率区间、置信度、失效条件 |
| `Scenario` 情景 | 组织几种互斥或部分互斥的发展路径 | 领先指标、转移条件、退出条件 |

事件有两组彼此独立的状态：

- **现实生命周期**：计划中、发生中、暂停、恢复、降温、已结束；
- **认知状态**：待核、部分支持、存在争议、已反驳、达到确认门槛。

把两组状态压成一个 `event.status` 会产生歧义。“事件已经结束”描述现实生命周期，“事件已确认”描述认知状态，它们可能同时成立，也可能分别变化。

分析置信度表示判断基础是否稳固；预测概率表示某种未来情况发生的可能性；风险等级还要考虑影响和处置代价。三者分别保存。没有校准样本时，预测使用概率区间和明确假设，不输出伪精确的小数。

### 5. 预警、任务和动作

| 对象 | 作用 | 关键语义 |
| --- | --- | --- |
| `Alert` 预警 | 通知某项风险达到业务关注条件 | 对象、等级、依据、有效期、升级/撤销条件 |
| `VerificationTask` 核验任务 | 补齐会改变结论的关键未知项 | 待核命题、所需来源、完成标准、负责人 |
| `MonitoringTask` 监测任务 | 在未来窗口持续采集指定信号 | 范围、频率、指标、截止和停止条件 |
| `Recommendation` 建议 | 向业务角色提出有条件的保护性措施 | 接收者、动作、理由、触发和撤销条件 |
| `ActionPolicy` 动作政策 | 决定哪些动作可自动执行、哪些需要审批 | 风险级别、权限、禁止项、回滚要求 |
| `ActionExecution` 动作执行 | 记录获批动作的实际执行过程 | 执行者、状态、输入版本、结果、失败原因 |
| `Outcome` 结果 | 记录真实结局和业务效果 | 事实标签、时间、影响、是否验证预测和建议 |
| `IntelReport` 情报报告 | 将事实、判断、预测和建议形成版本化产品 | 知识截点、接收对象、结论、变化摘要、来源 |

`Recommendation` 和 `ActionExecution` 必须分开。生成“复核航线”建议不等于系统已经通知航运负责人，也不等于相关方完成了复核。任何外部通知、风险等级发布和业务措施调整都要有执行回执。

动作权限分四级：

| 级别 | 例子 | 默认控制 |
| --- | --- | --- |
| A0 数据与草稿 | 刷新来源、创建内部核验任务、生成报告草稿 | 规则可自动执行，完整留痕 |
| A1 内部可逆调整 | 调整监测频率、增加关注标签、进入影子预警队列 | 满足政策后自动执行，可立即撤销 |
| A2 业务影响动作 | 对外发布预警、通知责任单位、调整业务风险等级 | 分析人员或责任人审批 |
| A3 禁止动作 | 实时打击目标、精确军事部署推断、进攻性行动建议 | 规则和模型双重拦截，不进入执行面 |

### 6. 学习与治理

| 对象 | 作用 | 关键语义 |
| --- | --- | --- |
| `Rule` 规则 | 表达确定性约束、检测、验证、研判或动作条件 | 类型、输入、窗口、条件、输出、版本 |
| `Policy` 政策 | 约束置信度、风险、审批、发布和安全边界 | 适用范围、优先级、冲突处理 |
| `ModelChangeProposal` 模型变更建议 | 保存 AI、分析人员或评测程序提出的结构/规则变化 | 变更原因、影响范围、候选补丁、提出者 |
| `EvaluationRun` 评测运行 | 在历史或影子数据上比较版本 | 数据截点、样本集、指标、失败样例 |
| `OntologyRelease` 本体发布 | 固化可部署的概念、关系、规则和政策版本 | 版本、依赖、兼容性、生效时间、回滚版本 |
| `DecisionTrace` 决策轨迹 | 说明一项建议或变更为何获批或拒绝 | 参与者、依据、异议、最终决定 |

模型变更和业务数据更新走不同通道。新事件只增加实例和新评估，不应静默修改概念定义；新概念或规则必须形成候选版本，完成评测后发布。

### 7. 关键关系

关系使用有方向、可约束的动词，少用无法计算的“相关”“关联”。同一对对象可以在不同时间和依据下建立多条关系，每条关系保留来源、有效期和版本。

| 关系 | 主体 → 客体 | 使用边界 |
| --- | --- | --- |
| `describes` 描述 | 来源材料 → 命题/事件 | 表示材料谈到什么，不表示内容为真 |
| `asserts` 主张 | 信息主体 → 命题 | 保留谁作出陈述及其原始措辞 |
| `observes` 观测到 | 传感器/分析人员 → 观测 | 绑定方法、覆盖和观测时间 |
| `derived_from` 派生自 | 派生结果 → 观测/数据集 | 绑定算法、参数和版本 |
| `supports` 支持 | 主张/观测/派生结果 → 命题/假设 | 标注直接性、独立组和适用字段 |
| `refutes` 反驳 | 主张/观测/派生结果 → 命题/假设 | 反驳强度受覆盖和可探测性约束 |
| `depends_on_source` 依赖来源 | 来源材料 → 原始稿源/通报/方法家族 | 用于独立性计算和传播链还原 |
| `located_in` 位于 | 对象/事件/观测 → 区域 | 使用事件发生时有效的空间边界版本 |
| `participates_in` 参与 | 人/组织/资产 → 事件 | 参与角色与“被提及”分开 |
| `affects` 影响 | 事件/风险 → 航线/设施/服务 | 需要影响层材料，不能由邻近关系直接推出 |
| `depends_on` 依赖 | 设施/服务 → 设施/服务 | 用于民用影响传播，保留依赖方向和强度 |
| `responds_to` 回应 | 事件/动作 → 事件 | 只有原始因果说明或经批准的分析评估才能建立 |
| `supersedes` 取代 | 新评估/报告/版本 → 旧评估/报告/版本 | 旧记录保留，不做原地覆盖 |
| `invalidates` 使失效 | 新材料/评估 → 假设/预测/建议 | 说明失效范围和原因 |
| `triggers` 触发 | 规则命中/风险 → 预警/任务/建议 | 绑定规则版本和触发输入 |
| `requires_approval` 需要审批 | 建议/动作 → 角色/审批策略 | 未批准前不得形成执行记录 |
| `executed_by` 执行者 | 动作执行 → 人员/系统 | 区分建议者、审批者和执行者 |
| `produces_outcome` 产生结果 | 动作执行 → 结果 | 用于评估建议是否有效 |
| `proposes_change` 提议变更 | AI/人员/评测 → 模型变更建议 | 候选关系不直接进入生产版本 |
| `evaluated_against` 对照评测 | 模型版本 → 样本集/旧版本 | 保存数据截点、指标和失败样例 |

因果关系必须比普通时序关系使用更高门槛。两个事件时间相近时先使用 `precedes` 或共同归入一个任务，不自动建立 `causes`、`responds_to` 或“同一指挥链”。

## 六、时间、版本和来源模型

### 1. 关键时间

至少分开保存以下时间：

| 时间 | 含义 |
| --- | --- |
| `event_time` | 事件实际发生或估计发生的时间 |
| `first_public_at` | 当前已知最早公开时间 |
| `publish_time` | 当前材料的发布时间 |
| `observed_at` | 传感器或分析人员取得观测的时间 |
| `ingested_at` | 系统接收材料的时间 |
| `known_at` | 该信息首次进入某一版分析视图的时间 |
| `valid_from` / `valid_to` | 规则、政策、对象属性或判断的现实有效期 |

内部计算统一使用 UTC，展示时生成 CST 和来源当地时间。所有历史回放以 `known_at` 截断，禁止让后续材料倒灌到早期判断。

### 2. 双时间和不可变版本

每项命题、评估和事件投影同时保存：

- 它描述的现实时间；
- 系统在何时知道并采用这项信息。

旧评估不做原地覆盖。新版本通过 `supersedes` 指向旧版本，并记录触发变更的新增材料、撤回的判断和动作变化。系统由此支持两个必要查询：

1. 现在基于全部已知材料如何判断；
2. 在某个历史截点，当时能够合理作出什么判断。

### 3. 来源依赖图

来源关系至少包含：转载、引用、翻译、摘要、共同采访、共同官方通报、同传感方法家族和派生计算。独立信息组由这张依赖图生成，允许分析人员修订。

大模型可以提出依赖关系候选，但不得仅凭文本相似度自动合并。标题相似可能来自共同稿源，也可能是多家媒体对同一事件的独立报道；最终判断需结合作者、引语、段落顺序、发布时间和原始链接。

## 七、规则模型

### 1. 六类规则

| 规则类型 | 处理内容 | 典型输出 |
| --- | --- | --- |
| 约束与归一规则 | 类型、必填字段、单位、时区、身份映射和关系基数 | 拒绝无效数据、生成映射候选 |
| 线索发现规则 | 基线偏离、空间进入、序列变化、缺失、聚合和来源触发 | 异常线索、候选事件 |
| 证据核验规则 | 时空对齐、独立组、支持/反驳、覆盖和负面发现 | 命题状态、证据缺口、核验任务 |
| 研判与预测规则 | 竞争性假设、诊断性指标、状态转移和预测窗口 | 假设排序、阶段判断、预测候选 |
| 风险与动作规则 | 影响、发生可能性、误判代价、权限和调整条件 | 预警、建议、审批任务 |
| 治理与学习规则 | 版本兼容、回放门槛、影子指标、安全边界和回滚 | 变更通过、拒绝或继续观察 |

复杂地理、轨迹和高频窗口计算不要求全部由本体平台执行。运行面或数据平台计算出带版本和来源的 `DerivedFinding`，本体规则负责解释其语义、组合证据和驱动工作流。

### 2. 规则的最小结构

每条生产规则至少包含：

- 稳定编码和版本；
- 业务目的、适用对象和空间范围；
- 输入类型、事件时间字段和数据新鲜度要求；
- 时间窗口、分组键、序列或聚合条件；
- 证据要求、独立性要求和负面发现口径；
- 命中后生成的判断、预警、任务或建议；
- 冷却、抑制、冲突优先级和失效条件；
- 自然语言解释模板；
- 负责人、生效窗口、测试样例和回滚版本。

阈值、权重和证据门槛都进入版本。规则命中记录保存输入引用、规则版本、中间结果和输出，不只保存一句告警摘要。

### 3. 判断变化示例

以两篇材料中的“暂停是否仍在持续”为例，规则可以按以下逻辑运行：

1. `pause_in_effect` 命题由双方暂停主张和一段时间内未观察到新直接行动支持；“未观察到”必须带连续来源覆盖。
2. 新的直接行动命题进入后，先分别核验行动方、目标、来向、命中和损害，不用一个字段确认整起事件。
3. 若“行动方恢复直接行动”达到事实门槛，则生成新评估，撤销“暂停仍在持续”的当前投影。
4. 系统同时建立“是否进入连续直接互攻”新命题，在 6、24、48 小时窗口采集反向行动和斡旋信号。
5. 风险规则根据直接行动、公开威胁、制裁、海事和市场等不同层次信息更新风险，但不得用市场上涨确认军事事实。
6. 动作规则更新约旦航线、航运保险和能源采购的复核建议，并保留下调条件。

这套逻辑的重点是派生新判断和任务，不是改写旧记录。

### 4. 规则冲突

规则冲突按以下顺序处理：安全政策优先于动作建议；字段级事实规则优先于事件级概括；直接观测优先于同源转载数量；新版本只在生效窗口内优先于旧版本；仍无法裁决的冲突转人工复核。

规则引擎不得把“无数据”当作 `false`。输入缺失、覆盖不足、来源失败和明确反证是四种不同状态。

## 八、预测模型

预测对象由未来命题、时间范围、概率区间、分析置信度、关键假设、领先指标、反向指标和失效条件组成。每次重判生成新版本，并保留旧预测到期后的结果评价。

预测采用多种方法协作：

- 状态转移和因果假设用于表达“什么条件会让局势升级、维持或缓和”；
- 时间序列和异常模型用于测量活动、市场和运行指标偏离；
- 历史相似案例只作为先验和比较材料，不直接决定当前结论；
- 大模型生成竞争性情景、遗漏因素和解释草稿；
- 规则和分析人员检查是否存在反证、混杂因素和越界外推。

预测到期后记录 `confirmed`、`partially_confirmed`、`refuted` 或 `not_observable`。只有可观测结局才能进入概率校准。样本积累后使用 Brier Score、可靠性曲线、误报率和漏报率检查模型是否过度自信；早期先积累统一标签，不急于训练复杂模型。

## 九、大模型参与方式

### 1. 适合交给大模型的工作

- 从长文中提取候选命题、主体、条件、时间和缺失字段；
- 识别转载、翻译、引用和同源材料候选；
- 生成实体别名、跨语言映射和可能的同一对象候选；
- 将自然语言规则草案转换为类型化规则候选；
- 提出竞争性假设、反证检索词和高区分度指标；
- 根据证据台账生成首报、更新报和面向不同对象的报告草稿；
- 从误报、漏报、人工修改和实际结果中提出本体或规则变更建议。

### 2. 不交给大模型独立决定的工作

- 将来源陈述直接提升为已确认事实；
- 自行给来源赋予永久可靠性分数；
- 在没有覆盖模型时把“未发现”解释为“不存在”；
- 自动发布高影响预警或对外报告；
- 未经回放和审批修改生产本体、规则、阈值或动作政策；
- 生成或执行进攻性行动建议。

### 3. 大模型产物的记录要求

每项 AI 候选保留模型标识、提示模板版本、检索资料清单、知识截点、结构化输出、理由摘要和人工处理结果。大模型输出先进入 `Proposal`，通过类型校验、来源绑定、规则检查和人工复核后，才能转为正式命题、规则或报告内容。

模型升级后，旧版本生成的判断不能静默重算。需要重算时创建新分析版本，并说明差异来自新增数据、提示变化、模型变化还是规则变化。

## 十、自动演化与受控进化

### 1. 三条反馈回路

**态势反馈**处理新材料。新观测触发命题、证据、评估、预警和任务更新，通常不改变本体结构。

**运行反馈**处理规则表现。分析人员的接受、驳回、降级、修改和动作结果形成标签，用于发现阈值不合理、来源评价过时、规则遗漏和报告不清楚。

**模型反馈**处理结构变化。多次出现无法表达的新对象、新关系、新事件模式或新动作需求时，大模型和业务专家共同生成 `ModelChangeProposal`。

### 2. 变更发布流程

模型变更按以下顺序处理：

1. 从失败案例、人工修订和新业务需求中定位具体缺口；
2. 生成概念、关系、约束、规则或动作模板补丁；
3. 检查命名冲突、循环依赖、类型错误和兼容性；
4. 在冻结的历史案例上回放，与现行版本对比；
5. 在实时数据上影子运行，不改变正式预警和动作；
6. 由本体负责人、业务分析负责人和安全责任人按影响范围审批；
7. 小范围启用，观察误报、漏报、延迟和资源消耗；
8. 达到门槛后发布，异常时回滚到上一版本。

结构变更、规则变更和动作政策变更使用不同审批强度。增加别名映射可以低风险自动合并；新增事实类型需要业务审核；改变预警阈值或动作权限必须经过回放、影子运行和责任人审批。

### 3. 判断是否真正进化

新版本至少在一项核心指标上改善，且其他关键指标没有明显退化：

- 关键主张的来源和证据可追溯率；
- 首份有用简报耗时和关键缺口发现时间；
- 误报、漏报和不必要升级比例；
- 预测概率的校准程度；
- 新证据进入后的纠错时间；
- 建议被业务接受、撤销和证明无效的比例；
- 人工复核工作量及高风险遗漏；
- 系统延迟、稳定性和运行成本。

评测必须使用时间冻结的留出案例。已经用于调规则的案例不能同时作为最终证明。现实结局不可观测的样本单独标记，不强行归入成功或失败。

## 十一、系统职责边界

| 能力 | `moye-v4-product` 数据加工面 | `doops-dev` 本体与规则面 | `gintbroker` 实时运行面 | AI/智能体 |
| --- | --- | --- | --- | --- |
| 外部源连接和原始存储 | 主责 | 保存引用和语义投影 | 保留特殊采集与热缓存 | 不直接保管凭据 |
| 清洗、去重、基线和批流计算 | 主责 | 读取结果及血缘 | 执行应用特有轻加工 | 提出映射和异常解释候选 |
| 稳定对象、命题、证据和版本 | 提供源映射 | 主责 | 消费并缓存当前投影 | 提取和补全候选 |
| 高频地理和时序规则 | 可做流式聚合 | 管理语义和规则元数据 | 热路径主责 | 不进入确定性执行热路径 |
| 语义核验、假设和分析评估 | 提供数据结果 | 主责 | 应用编排与展示 | 生成候选并辅助解释 |
| 预警、报告和动作流程 | 提供影响数据 | 保存规则、依据和审计 | 面向用户编排、展示和通知 | 生成草稿，不独立签发 |
| 模型演化 | 提供失败和质量指标 | 保存候选、评测和发布版本 | 影子对账和运行指标 | 提出变更候选 |

高频 AIS、ADS-B、行情和大体量影像不逐点入图。本体保存稳定对象、观测摘要、异常结果、证据引用和规则命中。这样既保留语义和追溯，也避免让图谱承担实时计算和大文件存储。

本方案描述目标模型，不判断上述项目当前已经完成到哪一步。实施前需现场核对接口、规则执行器、版本能力和运行约束，再决定哪些能力直接复用、哪些需要改造。

## 十二、最小可行模型

第一阶段不建设大而全的军事领域词典。先选择一个海事事件，完成以下最小对象：

1. `IntelCase`、`DecisionQuestion`；
2. `SourceArtifact`、`SourceActor`、`Proposition`、`Claim`；
3. `Observation`、`DerivedFinding`、`EvidenceLink`、`IndependenceGroup`；
4. `CoverageAssessment`、`NegativeFinding`；
5. `Event`、`Hypothesis`、`AnalyticAssessment`、`RiskAssessment`；
6. `Alert`、`VerificationTask`、`MonitoringTask`、`Recommendation`；
7. `Rule`、`Policy`、`IntelReport`、`OntologyRelease`。

第一阶段只实现四类关键规则：来源依赖归并、字段级证据核验、事件状态更新、核验任务和报告生成。预测概率和自动阈值学习先记录接口和结果标签，不作为上线门槛。

最小闭环的验收结果应当是：同一事件在新证据进入后能生成新版本判断；分析人员可以看到变化原因；旧版本可重放；关键未知项能转成任务；建议有明确调整条件；任何高影响发布都经过审批。

## 十三、建设顺序

### 第一阶段：建立可追溯的认知模型

- 固定命题、主张、观测、证据、来源依赖、覆盖和双时间字段；
- 选择两篇文档中的案例，固化初始判断、新事件和 24/48 小时更新版本；
- 支持字段级确认和历史截点回放；
- 输出主张—证据矩阵和版本差异。

### 第二阶段：让规则和动作可运行

- 接入基线、地理和时序派生结果；
- 建设核验、预警、建议、审批、撤销和持续监测状态；
- 将复杂轨迹计算留在数据或运行面，本体消费类型化结果；
- 形成规则命中解释和失败处理。

### 第三阶段：建立预测和效果校准

- 为竞争性情景配置领先指标、反向指标和状态转移；
- 冻结预测、知识截点和到期结果；
- 积累不少于 10 个历史事件和 5 个实时事件，覆盖升级、降温、假消息、冲突来源和数据空窗；
- 校准预测概率、预警阈值和负面发现分量。

### 第四阶段：运行受控的 AI 演化

- 让大模型生成映射、规则和结构变更候选；
- 建设自动回放、影子对账、差异解释和版本审批；
- 先放开低风险别名和映射建议，再逐步处理规则参数和概念变更；
- 动作政策与安全边界始终保留人工审批。

## 十四、验收要求

| 维度 | 最低要求 |
| --- | --- |
| 可追溯 | 所有关键判断都能回到命题、来源快照、采集时间、证据关系和规则版本 |
| 独立性 | 关键证据完成稿源、采集链和方法家族分组 |
| 时间一致性 | 能按知识截点重放首报、更新报和预测，不使用后验信息 |
| 负面发现 | 所有“未发现”均带覆盖、在线率、延迟、可探测性和漏检条件 |
| 纠错 | 新证据进入后生成新版本并列出撤回判断、置信度和动作变化 |
| 预测 | 事实、预测概率和分析置信度分开；到期后保存结果标签 |
| 动作 | 每条建议有接收者、依据、有效期、升级和撤销条件；高影响动作有审批和回执 |
| AI 治理 | 所有 AI 产物先进入候选区；生产变更经过校验、回放、影子运行和审批 |
| 安全 | 不生成或执行进攻性建议；凭据、敏感原文和大文件按许可分层保存 |
| 回滚 | 本体、规则和政策可独立回退，当前投影可以重建 |

## 十五、主要风险

| 风险 | 可能表现 | 防护 |
| --- | --- | --- |
| 把知识图谱规模当作完成度 | 对象和关系很多，关键判断仍不可追溯 | 按真实案例和判断闭环验收 |
| 数值置信度制造精确感 | 未校准分数直接驱动预警 | 早期使用分级和依据；校准后再用于自动决策 |
| 大模型确认偏差 | 模型围绕起始新闻寻找佐证 | 强制生成竞争性假设、反证和缺失字段 |
| 来源评分固化偏见 | 某来源被永久高估或低估 | 按信息类型和时间范围评价，允许复核 |
| 后验信息污染回放 | 用后来材料美化早期判断 | 所有实例和评估使用 `known_at` 截断 |
| 规则自动演化失控 | 新阈值降低误报却增加漏报 | 留出集、影子运行、多指标 Gate 和一键回滚 |
| 高频数据压垮本体 | 航迹点、影像和行情全部入图 | 只保存语义投影、摘要和引用 |
| 建议越过安全边界 | 模型生成进攻性或未经授权的动作 | A0—A3 权限、禁用策略、人工签发和审计 |
