# 霍尔木兹动态本体样板数据准备详细评估与实施方案

## 一、结论：先补一份可复核证据包，不先改平台

本文细化《候选预警事件的动态本体展示价值与数据准备分析》中选定的主故事：以 E“外交改善与实际通航风险背离”为主线，用 D“美伊争夺霍尔木兹控制权”形成主张冲突，用 A“霍尔木兹航运持续异常”检验物理世界是否恢复，再用 G“美国从军事打击转向经济／海上施压”说明风险驱动因素发生变化。

最快、风险最低的做法不是等待现有 AIS 历史点补成连续航迹，也不是立即改 `doops-dev` 或 `gintbroker`，而是在 **2 个工作日内冻结一份小型、可追溯、可重复计算的静态证据包**：

1. 4—6 条美、伊、阿曼关键官方主张及其原文快照；
2. 一套定义固定的霍尔木兹 2026 年 8 月 1—25 日日通航序列，第一版直接采用 IMF PortWatch 公开指标；
3. 同一时间窗的 NAVAREA IX、IMO 等正式海事通告；
4. 一张来源家族与版本关系表，把官方原文、Reuters 转述、GDELT 聚类和 RSS 条目连起来，禁止按文章条数重复计票。

现有系统可以明显缩短准备时间，但不能直接交付这四项：

- `trs_gisa` 已保存大量 GDELT／RSS 标题、摘要、URL 和中文标题，可用于发现线索和筛选材料；没有保存事件窗内对应的美、伊、阿曼官方原文，也没有正文。
- 上一份文档所写“NAVAREA IX 当前为 0 条”只对 `source_items` 这一张统一来源表成立。专题运行队列 `topic_runtime_sync_jobs` 实际已有 192 个 NAVAREA IX 证据装配任务，事件窗内有 12 个不同通告。因此正确结论是：**系统已经抓取并规范化过 NAVAREA，但数据落在专题运行快照，不在统一来源／翻译链中。**
- `dy_track.track_observation` 在样例框和事件窗内共有 5,887 条 AIS 观测、1,440 个不同 MMSI，但每天每船观测点中位数均为 1；没有任何“单船单日至少 5 点且最大间隔不超过 30 分钟”的航段。这些点只能用于覆盖审计或个别位置佐证，不能直接计算完整穿越数。
- `gintbroker` 的实时 AIS 是面向地图展示的内存热数据，当前测试环境 AIS proxy 未连接，也不是历史分析库。第一版不应依赖它补历史航段。
- IMF PortWatch 公开接口已经给出 8 月 1—25 日逐日总通航量及油轮、货船拆分；它能快速成为第一版可复算行为指标，但必须保存查询参数、响应快照、抓取时间和指标定义，不能只抄新闻里的“约多少艘”。

第一版完成标准不是“所有源都接进平台”，而是业务人员可以从证据包回答四个问题：谁说了什么、船舶行为实际怎样、正式海事信息是否支持、为何当前风险维持或变化。

## 二、固定本轮要证明的命题

本轮只围绕一个风险对象：**霍尔木兹安全通航风险**。不扩展到 B、C、F 三个独立袭击事件，也不做全量美伊冲突数据治理。

| 编号 | 命题 | 需要的证据 | 第一版允许的结论强度 |
| --- | --- | --- | --- |
| C1 | 外交层面出现缓和或临时通航安排信号 | 美国、伊朗、阿曼原始发布，辅以 Reuters 转述 | “某方公开主张／多方正在磋商”，不自动等于通航已恢复 |
| C2 | 美伊对海峡控制、扫雷或航行安排存在相互冲突的公开主张 | 双方原始声明、发布时间、原文上下文 | “主张冲突已确认”，不裁定哪一方实际控制 |
| O1 | 外交改善后，实际商业通航仍显著低于基线 | PortWatch 同口径日度序列；有条件时用授权 Kpler／LSEG 或合格 AIS 航段复核 | “公开指标显示持续受扰”；只有覆盖和航段 Gate 通过后才报告自算穿越数 |
| M1 | 同期仍存在影响航行安全的正式通告或事故信息 | NAVAREA IX、IMO，必要时补 UKMTO／港口当局 | “正式通告仍有效／已取消／发生版本变化”，不从通告推断攻击方 |
| P1 | 后期压力方式增加经济制裁或海上措施 | Treasury／OFAC 等官方发布，新闻只作线索 | “施压工具发生变化”，不把市场波动单独当作行动证据 |

每个命题保留 `supported`、`contradicted`、`insufficient` 三类证据关系。风险评估只使用在该评估时间之前已经发布且已经采集的材料，避免用后来信息改写当时判断。

### 3.2 官方原始主张的当前缺口

在 `source_items.url` 和主文本中复核后，事件窗没有形成 White House、CENTCOM、Oman MFA、U.S. Treasury／OFAC、IMO、NAVAREA IX 或 UKMTO 的直接来源记录。累计数据中只有 4 条 `centcom.mil` 的公开研究种子，且不在事件窗。

因此当前状态是：

- **已获取：** 大量转述这些主张的 GDELT／RSS 候选；
- **已翻译：** 绝大多数候选主标题；
- **已保存：** 标题、摘要、URL、时间和聚类结构；

- **不可由翻译补救：** 没有正文时，标题翻译不能替代原文上下文。

### 3.5 `dy_track` 的历史 AIS 到底有多少

这次沿用现有采集任务的样例框 `lon 54—57.2, lat 24—27.2`。它覆盖霍尔木兹西侧及周边，是诊断用包围框，不是最终的 TSS（Traffic Separation Scheme，分道通航制）或穿越门线。

在 2026 年 8 月 1—25 日共有：

- 5,887 条观测，1,440 个不同 `object_id`（这里为 MMSI）；
- 1,042 艘在整个 25 天内至少 2 点，388 艘至少 5 点，131 艘至少 10 点，955 艘跨多日出现；
- 213 艘的经度跨度至少 1°，但 **0 艘**同时满足“至少 5 点且最大相邻点间隔不超过 30 分钟”；
- 每天每船点数中位数均为 1；8 月 25 日只覆盖 14 个有记录小时；
- 入库延迟中位数约 2,051 秒，P95 约 41,252 秒，1,518 条超过 1 小时；
- `call_sign` 全部缺失，IMO 缺 346 条，船舶类别缺 3 条，船型代码缺 1,269 条；原始 JSON 中也没有目的地、航行状态或供应方字段；
- 有 1 个 MMSI 对应多个 IMO、6 个 MMSI 对应多个名称、1 个对应多个类别、2 个对应多个船型代码，需要保留冲突而不是静默覆盖；
- `source_id`、`content_hash` 及“对象 + 时间 + 位置”在该窗口都逐行唯一，说明 `source_id` 是上游记录标识，不是供应商标识，不能用它统计独立数据源。

采集控制表也不能证明目标海域连续覆盖：事件窗的 `coverage_bucket` 只有 1,438 条 `best_effort` 记录，截止到 8 月 23 日；相关运行共有 170 次 `succeeded`、2 次 `partial`、1 次 `failed`、1 次 `cancelled`，但保存数量是全局任务量，不是样例框内完整度。1,511 个 `query_slice` 均为 `best_effort`，其中 1,487 个发生切分。“任务成功”只表示采集器完成了其可执行请求，不等于供应方返回了目标海域所有 AIS 报告。

## 四、原 6.1 四类必需数据如何准备

### 4.1 原始主张：回到发布者，不重抓全部新闻

#### 采集范围

只选能改变 C1、C2、P1 判断的 4—6 条主张：

1. 美国关于暂缓攻击、扫雷、护航或海峡控制的公开发布；
2. 伊朗关于控制、限制、通航条件或回应的公开发布；
3. 阿曼关于临时通航安排或外交磋商的公开发布；
4. G 阶段补 1 条 Treasury／OFAC 制裁原文；
5. 如 Reuters 明确引用了另一份会改变判断的原文，再增加，但总量不超过 6 条。

优先顺序为官方 HTML／PDF、官方社交账号或可验证转录、Reuters 等权威媒体转述。找不到原文时，允许保留 Reuters 转述，但必须标为 `indirect_claim`，不能伪装成官方原文。

#### 治理动作

每条原始文件至少记录：

| 字段 | 含义 |
| --- | --- |
| `document_id` | 稳定内部 ID，不使用标题作主键 |
| `publisher`、`publisher_domain` | 原始发布者及域名 |
| `canonical_url` | 去除跟踪参数后的原始 URL |
| `published_at`、`time_precision`、`timezone` | 发布时间、精度和时区 |
| `collected_at`、`knowledge_cutoff_at` | 实际取得时间和本次评估知识截止时间 |
| `content_sha256`、`snapshot_path` | 内容 hash 与本地快照位置 |
| `language`、`title_original`、`body_excerpt_original` | 原始语言、标题和与命题直接相关的短摘录 |
| `title_zh`、`body_excerpt_zh`、`translation_status` | 中文译文、翻译状态和必要人工复核 |
| `version_of`、`supersedes` | 修订、替代或撤回关系 |

只翻译标题和与命题直接相关的 1—3 段，不为了样板抓取和翻译整站。自动翻译后由一名分析员核对主体、否定词、条件词、时间和情态词；这些词会直接改变“已经发生”“计划发生”“有条件发生”的判断。

#### 现成可复用与必须补齐

- 复用 `source_items` 的 GDELT／RSS 候选和已有中文标题，快速定位 4—6 条材料；
- 复用 `item_translations` 与 `translations` 的字段级翻译和内容复用机制；
- 新增的官方网页先冻结为证据包文件，不等待全站采集器上线；
- 必须补齐官方原文快照、内容 hash、版本关系和 Reuters 引用关系；
- 不把 16 篇 Reuters 逐篇翻译成 16 票证据，而是拆为 4—6 个原始主张家族。

### 4.2 可复算通航序列：第一版用 PortWatch，AIS 只做质量旁证

#### 第一版采集方法

从 IMF PortWatch 的 `Daily_Chokepoints_Data` 查询 `portid='chokepoint6'`，冻结三个窗口：

- 事件窗：2026-08-01 至 2026-08-25；
- 近端基线：2026-07-01 至 2026-07-31；
- 同历日基线：2025-08-01 至 2025-08-25。

保存字段只需 `date, portid, portname, n_total, n_tanker, n_cargo, capacity` 及必要船型分项。`n_total = n_tanker + n_cargo`；`n_cargo` 又是集装箱、干散货、杂货和滚装等分项合计，不能把总数和分项再次相加。

当前公开结果显示：2026 年 8 月 1—25 日共 120 艘次，日均 4.80，最低 1、最高 10，其中油轮日均 2.00、货船日均 2.80；2026 年 7 月日均 10.19；2025 年同期日均 92.76。第一版可以据此表达“该公开同口径指标仍显著低于近端及历史基线”，但必须同时展示来源、窗口和口径，不把它说成“所有船舶真实总数”。

#### 治理动作

1. 原始 JSON 原样保存，另生成规范 CSV；两者都计算 SHA-256。
2. 在 manifest 中保存完整查询条件、接口 URL、抓取时间、返回条数和字段说明。
3. 检查日期是否连续、`n_total=n_tanker+n_cargo` 是否逐日成立、是否有负数或重复日期。
4. 冻结基线窗口，不在看到结果后挑选对比期。
5. 如接口后来修订，保留新旧快照和 `supersedes` 关系，不覆盖旧版本。
6. 图表只展示同一版本数据；标题写明“PortWatch 商船日通航指标”，不简称为“真实 AIS 船数”。

#### Kpler／LSEG 和本地 AIS 的位置

Kpler／LSEG 不是第一版阻断项。当前 `trs_gisa` 只有 3 行 GDELT 内容提到 Kpler、2 个逻辑 ID；LSEG 为 0，均没有授权原始时序。如果能在 1 个工作日内取得授权摘要，应作为另一份航运指标保存并注明方法；否则不等待。

本地 `dy_track` 当前不能成为日穿越序列。继续清洗现有稀疏点不会凭空产生缺失的中间航迹；只有取得更密集的原始 AIS 后，才进入第六节的航段治理。

### 4.3 正式海事信息：先导出已有 NAVAREA，再补权威缺口

#### 采集与治理

第一版从 `topic_runtime_sync_jobs.source_snapshot_json` 导出事件窗 12 条 NAVAREA IX 记录，保留：

- 通告号、原始标题和全文；
- DTG、发布时间、采集时间和时间精度；
- 原始坐标、规范坐标和范围文字；
- `LISTED_IN_FORCE`／`CANCELLATION` 状态；
- `cancels` 与 `cancelled_by` 版本关系；
- `contentDigest`、任务状态和失败摘要。

对失败的 1 条任务只做一次定向重取或人工获取；若仍失败，保留失败记录和原始 URL，不因样板需要静默删除。

随后只补与命题直接相关的 IMO／UKMTO／港口当局材料：

- IMO 的 Middle East / Strait of Hormuz 专页用于官方航行安全背景和事件登记；
- UKMTO 如有与同一时间、区域直接相关的警示，作为独立通告家族；
- 阿曼官方通航安排与外交声明按“官方主张”保存，不能与 NAVAREA 混为同一来源类型。

通告必须按“通告号 + 版本状态”呈现。已取消表示这份通告不再有效，不等于相关风险从未发生；被后续通告替代时必须沿版本边连接。

#### 当前缺口

- 已有 NAVAREA 规范记录，但尚未进入统一来源表和翻译表；
- 没有结构化 UKMTO 来源；
- IMO 及港口当局页面没有在 `source_items` 留存；
- 现有专题结果未把通告版本、适用区域和风险对象完整展示给业务人员。

### 4.4 来源家族和版本：这是去重，不是再建一个新闻库

| 字段 | 例子 |
| --- | --- |

| `relation` | `quotes`、`summarizes`、`reposts`、`version_of`、`supersedes`、`cancels` |

| `basis` | URL、明确引述、相同正文 hash、人工核对 |

计票规则很简单：

- 同一官方声明被 Reuters、GDELT 和多个 RSS 源转述，仍只算一个“官方主张家族”；
- PortWatch、授权 Kpler／LSEG、合格的本地 AIS 航段是行为观测家族，必须分别说明方法和覆盖；

- 不同家族之间相互支持时提高证据广度，同一家族内的转载只提高传播可见性。

## 六、AIS 覆盖率和航段质量应如何治理

### 6.1 先定义三个空间对象

不要直接用当前大包围框计算穿越。先由海事业务人员冻结三个版本化几何对象：

1. `hormuz_aoi_v1`：用于召回候选轨迹的宽范围区域；
2. `hormuz_west_gate_v1` 与 `hormuz_east_gate_v1`：横跨合法通航方向的东西门线或窄多边形；
3. `hormuz_tss_v1`：依据 IMO／阿曼发布材料整理的分道通航参考区，仅用于航段判定和展示。

每个对象保存 GeoJSON、坐标系、来源、制作人、审核人和版本。专题中心点不能替代门线，诊断包围框也不能替代 TSS。

### 6.2 覆盖率分成四层，逐层过 Gate

| 层级 | 要回答的问题 | 核心指标 | 当前结论 |
| --- | --- | --- | --- |
| G0 采集任务 | 请求是否正常发出并得到响应 | `task_run` 状态、`query_slice` 状态、错误和重试 | 有大量成功任务，但都是 `best_effort` |
| G1 时空可见 | 每个时段、每个门线附近是否有足够报告 | 15 分钟桶有数、零桶、空间网格有数、上游健康 | 当前控制表不能证明完整，8 月 25 日有 10 个零小时 |
| G2 单船连续 | 同一 MMSI 能否形成可信航段 | 点数、最大间隔、速度、跳点、时间顺序 | 0 艘通过“≥5 点且最大间隔≤30 分钟” |
| G3 完成穿越 | 航段是否依次穿过两道门线 | 入门时间、出门时间、方向、唯一 MMSI | 当前不能计算 |

任何一天只有 G0/G1 而没有 G2，最多报告“当日采集到 N 条记录、N 个 MMSI”；不能报告“完成 N 次穿越”。

### 6.3 原始观测清洗

按 MMSI、观测时间排序后执行最小治理：

1. 校验 MMSI 格式、经纬度范围和时间；非法记录进入 reject 表，不静默修正。
2. 以稳定的上游记录 ID、内容 hash、观测时间去重；保留首次、末次采集时间。
3. AIS 缺省值保持缺失语义：`heading=511` 是不可用，`SOG>=102.2` 是不可用，不得在分析层直接写成 0。展示层可回退到 COG，但同时保留 `heading_available=false`。
4. 标记速度突变、位置跳跃和不可能的时间倒序；异常点保留原始值并从航段判定中排除。
5. MMSI 对多个 IMO／名称／船型时生成 identity conflict，按时间窗和可信来源人工确认，不覆盖历史值。
6. 船型代码保存原码、字典版本和规范类别；未识别时为 `unknown`，不能默认为货船或油轮。

`dy-track-explorer/internal/storage/enrichment.go` 只能把原始 JSON 中已经存在的键投影为标准字段。事件窗原始 JSON 没有 `callSign`、目的地、航行状态和供应方标识，因此再次跑 enrichment 也无法补出这些字段。

### 6.4 航段构建和完成穿越判定

第一版自算 AIS 穿越必须同时满足：

- 同一 MMSI、同一 UTC 日或连续窗口内至少 5 个有效点；
- 相邻点最大间隔不超过 30 分钟；
- 去除异常点后速度和位移连续，没有明显跳点；
- 航段按时间顺序进入一侧门线、通过 `hormuz_tss_v1`、离开另一侧门线；
- 东向与西向分别计数；同一 MMSI 同一方向的重复门线抖动合并为一次；
- 输出 `segment_id`、首末时间、方向、点数、最大间隔、质量标志和原始观测引用。

30 分钟和 5 点是本次样板的初始最低 Gate，不是永久行业标准。取得实际供应方采样频率后应先用一小批人工标注航段校准；如果采样本身比 30 分钟更稀，应该更换或补充数据源，而不是放宽阈值直到现有数据“通过”。

掉头、停留和 AIS 消失是后续派生事件，必须建立在合格航段上：

- 掉头：航向反转且持续，不能由两个孤立点判断；
- 停留：低速持续超过规定时间并位于合适区域，未知 SOG 不算 0；
- AIS 消失：需要消失前连续航段、区域覆盖正常和后续重新出现，当前数据无法区分主动关闭与采集缺口。

### 6.5 每日覆盖与发布规则

建议把每天的结果明确标成三种状态：

| 状态 | 条件 | 对外用语 |
| --- | --- | --- |
| `VALID` | G1 覆盖检查通过，且合格航段可形成稳定穿越计数 | “当日观测到 N 次符合口径的完成穿越” |
| `PARTIAL` | 有数据且可形成部分航段，但时空覆盖不完整 | “当日可见穿越至少 N 次；不能作为完整总量” |
| `UNUSABLE` | 无法形成连续航段或存在大面积缺口 | “当日数据不可用于穿越统计” |

在引入密集 AIS 后，G1 的初始建议值是：目标窗口内 15 分钟时间桶非空率不低于 90%，东西门线附近均有观测，采集器健康与上游响应没有连续 30 分钟以上中断。最终阈值由供应方正常采样基线校准后冻结。现有 8 月样例应整体标为 `UNUSABLE_FOR_TRANSIT_COUNT`。

### 6.6 数据从哪里补

优先级如下：

1. **P0：** 直接使用 PortWatch 日度聚合，完成第一版故事；
2. **P1：** 向已有合法 AIS 供应渠道申请霍尔木兹事件窗的历史明细，要求包含 MMSI、观测时间、经纬度、SOG、COG、heading、船型、IMO／名称、供应方标识和覆盖说明；
3. **P1：** 如无法取得历史明细，开始连续采集未来 3—7 天的小范围密集 AIS，先证明治理链能产出合格航段，再用于后续演示；
4. **可选复核：** 获得授权 Kpler／LSEG 同口径摘要后，与 PortWatch 和自算 AIS 并列，不以新闻转述代替原始时序。

不要立即对当前 `dy_track` 发起大规模回填。最新点已推进到 9 月 7 日，但采集仍有积压迹象；在确认上游能提供足够密度前，扩大回填只会增加稀疏记录量，不会解决航段质量。

```sql
         bool_or(
           t.status IN ('ok', 'dictionary')
           AND it.field_name IN ('title', 'headline', 'headline:0')
         ) AS primary_zh
  FROM item_translations it
  JOIN translations t USING (translation_id)
  GROUP BY it.item_id
), b AS (
  SELECT s.*,
         lower(concat_ws(' ', s.title_original, s.summary_original, s.body_original)) AS txt,
         coalesce(tr.primary_zh, false) AS primary_zh
  FROM source_items s
  LEFT JOIN tr USING (item_id)
  WHERE s.source_id IN ('news_rss_aggregate', 'gdelt_global_incidents_limited')
    AND s.event_time_utc >= '2026-08-01T00:00:00'
    AND s.event_time_utc <  '2026-08-26T00:00:00'
)
SELECT source_id,
       count(*) AS rows,
       count(DISTINCT source_item_id) AS logical_items,
       count(*) FILTER (WHERE nullif(trim(body_original), '') IS NOT NULL) AS body_rows,
       count(*) FILTER (WHERE primary_zh) AS primary_zh_rows,
       min(event_time_utc), max(event_time_utc)
FROM b
GROUP BY source_id
ORDER BY source_id;

COMMIT;
```

```sql
BEGIN READ ONLY;

WITH base AS (

  FROM base b
  CROSS JOIN LATERAL (
    VALUES
      ('hormuz',
       b.primary_txt LIKE '%hormuz%',
       (b.primary_txt || ' ' || b.normalized_txt) LIKE '%hormuz%'),
      ('hormuz_control',
       b.primary_txt LIKE '%hormuz%'
         AND (b.primary_txt LIKE '%control%' OR b.primary_txt LIKE '%seiz%'
              OR b.primary_txt LIKE '%blockad%' OR b.primary_txt LIKE '%mine%'),
       (b.primary_txt || ' ' || b.normalized_txt) LIKE '%hormuz%'
         AND ((b.primary_txt || ' ' || b.normalized_txt) LIKE '%control%'
              OR (b.primary_txt || ' ' || b.normalized_txt) LIKE '%seiz%'
              OR (b.primary_txt || ' ' || b.normalized_txt) LIKE '%blockad%'
              OR (b.primary_txt || ' ' || b.normalized_txt) LIKE '%mine%'))
```

### 10.5 AIS 逐日记录、对象、连续性和延迟

```sql
BEGIN READ ONLY;
SET LOCAL statement_timeout = '180s';

WITH base AS (
  SELECT id, observed_at, object_id, collection_delay_seconds
  FROM track_observation
  WHERE dataset = 'ais'
    AND observed_at >= TIMESTAMPTZ '2026-08-01 00:00:00+00'
    AND observed_at <  TIMESTAMPTZ '2026-08-26 00:00:00+00'
    AND geom && ST_MakeEnvelope(54, 24, 57.2, 27.2, 4326)
), sequenced AS (
  SELECT b.*,
         lag(observed_at) OVER (
           PARTITION BY observed_at::date, object_id
           ORDER BY observed_at, id
         ) AS previous_at
  FROM base b
), object_day AS (
  SELECT observed_at::date AS utc_date,
         object_id,
         count(*) AS points,
         max(extract(epoch FROM observed_at - previous_at))
           FILTER (WHERE previous_at IS NOT NULL) AS max_gap_s
  FROM sequenced
  GROUP BY observed_at::date, object_id
), daily AS (
  SELECT observed_at::date AS utc_date,
         count(*) AS records,
         count(DISTINCT object_id) AS objects,
         count(DISTINCT date_trunc('hour', observed_at)) AS observed_hours,
         percentile_cont(0.95) WITHIN GROUP (ORDER BY collection_delay_seconds) AS delay_p95_s
  FROM base
  GROUP BY observed_at::date
)
SELECT d.utc_date, d.records, d.objects, d.observed_hours,
       count(*) FILTER (WHERE o.points >= 2) AS objects_2plus,
       count(*) FILTER (WHERE o.points >= 5) AS objects_5plus,
       count(*) FILTER (WHERE o.points >= 10) AS objects_10plus,
       percentile_cont(0.5) WITHIN GROUP (ORDER BY o.points) AS median_points_per_object,
       count(*) FILTER (WHERE o.points >= 5 AND o.max_gap_s <= 1800) AS gap30m_and_5plus,
       round(d.delay_p95_s::numeric, 1) AS delay_p95_s
FROM daily d
JOIN object_day o USING (utc_date)
GROUP BY d.utc_date, d.records, d.objects, d.observed_hours, d.delay_p95_s
ORDER BY d.utc_date;

COMMIT;
```

### 10.6 AIS 字段完整性和身份冲突

```sql
BEGIN READ ONLY;

WITH b AS (
  SELECT object_id, registry_id, name_or_model, category, vessel_type_code,
         call_sign, heading, sog, cog, length, collection_delay_seconds
  FROM track_observation

    AND observed_at >= TIMESTAMPTZ '2026-08-01 00:00:00+00'

    AND geom && ST_MakeEnvelope(54, 24, 57.2, 27.2, 4326)

       count(DISTINCT object_id) AS objects,
       count(*) FILTER (WHERE nullif(trim(registry_id), '') IS NULL) AS missing_imo,
       count(*) FILTER (WHERE nullif(trim(call_sign), '') IS NULL) AS missing_call_sign,
       count(*) FILTER (WHERE nullif(trim(category), '') IS NULL) AS missing_category,
       count(*) FILTER (WHERE nullif(trim(vessel_type_code), '') IS NULL) AS missing_vessel_type,
       count(*) FILTER (
         WHERE CASE WHEN trim(heading) ~ '^[0-9]+([.][0-9]+)?$'

         WHERE CASE WHEN trim(sog) ~ '^[0-9]+([.][0-9]+)?$'

       ) AS unavailable_sog,
       count(*) FILTER (
         WHERE CASE WHEN trim(length) ~ '^[0-9]+([.][0-9]+)?$'
                    THEN trim(length)::numeric = 0 ELSE false END
       ) AS zero_length
FROM b;

COMMIT;
```
