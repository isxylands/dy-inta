### 2.3 必须保留并纠正的旧语义

1. 本目标是“区域航运安全风险窗口”，不是具体攻击目标识别。
2. 新闻解决“出现了什么主张”，证据矩阵解决“可信到什么程度”；标题中的强断言不能直接升级事实状态。
3. 6 月 14/21/23 JMIC 更新只能作为后验核验，`score_delta=0`，不能回填 6 月 9-12 历史评分。
4. “全面关闭”必须建成独立 `closure_claim`；通行仍持续或证据不足时状态为 `refute`/`pending`，不得隐藏反证。
5. AIS 只支持区域活动、目的港、原始速度分布和质量说明；不证明攻击、拦截、故意关闭 AIS 或行动意图。
6. ADS-B 只支持区域活动背景和覆盖质量；不证明军事属性、空中支援或打击行动。
7. 设施目录回答“需要保护和监测谁”，不回答“是否受损或恢复”；军事基地目录不进入客户或内部本场景包。
8. 三个 bbox 只是内部粗筛选范围；从通用地理 WKT 裁剪出的几何也只能标为 `derived_reference_polygon`，未经责任人审批不得升级 `approved_polygon`。
9. 源文档 25/45/62/58 分数是草案，不是验收常量。执行必须按冻结规则和当时可见证据重算；如果 6 月 11 日达不到保护性准备门槛，应诚实保留 `elevated`/`monitoring`。
10. 数据盘点已确认 `IR_HKEY` 不是 AIS 唯一行 ID；本计划禁止把它用作唯一去重键。
11. 低速阈值和 AIS 速度单位尚未冻结；在确认前只展示原始速度分箱和质量提示，不复刻来源不明的“低速点数”。

## 3. 推荐方案和数据契约

### 3.1 实现策略

采用“源数据原地只读、外部磁盘分块派生、事实/主张/后验分层、仓库内小型发布快照、`gintbroker` 通用专题展示”的方案：

1. 先冻结目标、输入 hash、来源、授权、时间相位和不能下结论项。
2. 公开主张、官方发布、海事通告、结果事件分别落表；同一新闻转载先聚类再计权。
3. AIS 只读取 6 月月表并按真实事件时间筛 6 月 9-12 日；ADS-B 只读取对应 4 个日文件。
4. 原始口径和去重口径并存；原始基线用于对账，客户页面默认使用去重/聚合口径。
5. 遥测只输出 AOI/日期聚合，不提交逐点轨迹、MMSI/IMO/ICAO、呼号或可逆映射。
6. 设施只输出公共保护对象和泛化位置；图片默认不入包，损伤/恢复状态固定为 `not_assessed`。

### 3.6 AIS/ADS-B 派生契约

AIS：

- 业务时间优先 `IR_LASTTIME`；解析失败记录质量码，不用文件名/月名替代。
- `IR_HKEY` 仅保留为源字段摘要，不作为唯一行 ID。
- 去重键固定为 `IR_MMSI + (IR_POSITION_RECEIVED or IR_LASTTIME) + IR_LAT + IR_LON + IR_SPEED + IR_COURSE`；若后续取得稳定 source event ID，再新版本迁移。
- 先按时间和 AOI 过滤，再对小结果集去重；不得把全月逐点轨迹写入仓库。
- `IR_MMSI/IR_IMO/IR_CALL_SIGN` 和可逆映射只留外部工作区；仓库只输出日/AOI 聚合。
- 速度单位和低速阈值未确认前，输出 `speed_missing_count`、`speed_negative_count` 和原始数值分箱，不输出 `low_speed_count` 客户结论。
- `IR_DESTINATION` 只输出规范化类别和聚合计数；小计数按客户 Gate 做抑制，避免重识别。

ADS-B：

- 事件时间优先有效 `IR_LASTTIME`，其次解析 `source_date`，最后才允许文件名日级 fallback。
- `id` 只有通过唯一性测试后才能作为去重键；否则使用 `icao + event_time/source_date + lat + lon + alt + spd + trak`。
- 忽略所有 `._*.csv`。
- `reg/type/call/opicao/cou/mil/interested/warning_level` 缺失或未经核验时，不做身份、军事或关注属性推断。
- `spd` 负值/缺失、`alt` 缺失或单位未知只进入质量统计；不生成“低空”“高速”“军事活动增强”信号。
- 客户输出仅保留日期/AOI/原始行数/去重行数/唯一 ICAO 数量/缺失率/质量说明，不输出逐点轨迹或 ICAO。

两类摘要统一字段：

- `summary_date`、`aoi_id`、`count_mode`
- `row_count`、`unique_target_count`、`duplicate_count`
- `time_fallback_count`、`invalid_coordinate_count`
- `identity_missing_count`、`speed_missing_count`、`speed_negative_count`
- `quality_level`、`quality_note`、`source_ref`

### 3.8 评分和证据语义

沿用相邻规则文档的可解释权重作为候选规则库，但按本数据可用性启停：

| 规则 | 候选分值 | 本目标启用条件 |
| --- | ---: | --- |
| 公开风险主张升级 | +20 | `visible_at` 已知，转载聚类完成；同一 source family 只计一次 |
| 多源新闻一致 | +10 | 两个独立 source family，且不是相互转载 |
| 权威海事通告支持 | +20 | 通告在评分时间前已公开；6 月 14/21/23 后验更新不得回填 |
| AIS 区域候选 | 0 至 +10 | 单位/阈值/质量已冻结，且只表达通行背景；质量不足时为 0/context |
| ADS-B 区域背景 | 0 至 +5 | 只作背景；身份/速度语义不足时不得单独升分 |
| 证据矛盾 | -20 | 有独立反证或“全面关闭”与持续通航冲突 |
| 数据质量不足 | -10 | 时间、单位、覆盖或身份不足影响结论 |

本目标禁用“近距离小型船只活动”“军事航空活动增强”“背景军事部署”等规则，除非未来另有合法、可核验、非进攻性数据和单独评审。

分数区间沿用：`0-29 background`、`30-49 elevated`、`50-69 protective_readiness`、`70+ verify_now`。但页面客户动作统一为提升监测、二次确认、通知、持续观察和报告归档。分数只是证据组织方式，不是概率或确定性预测。

共享 bundle schema 的 `level` 枚举使用兼容并集：`background`、`elevated`、`protective_readiness`、`verify_now`、`event_response`、`monitoring`。本专题只生成前四类；`event_response/monitoring` 保留给 5 月单事件等已存在专题。前端按配置/文案渲染，不把 level 写成场景专用分支。

硬 Gate：

1. `context`、ADS-B 背景或单一新闻 family 不能单独进入 `protective_readiness`。
2. 进入 `protective_readiness` 至少需要两个独立、评分时已可见的证据 family，其中至少一个是权威海事/港口来源或经质量 Gate 的同 AOI 运营变化。
3. 6 月 14/21/23 后验证据只增加结果置信度，不改变历史分数。
4. 源文档 25/45/62/58 只作为旧草案记录在 `assumptions.md`，不得写成测试期望。
5. 每次分数变化必须绑定 `evidence_refs`、`visible_at_max`、`rule_version`、`quality_notes` 和 `not_yet_known`。

### 6.1 样本选择

- 设施正例：有来源和泛化位置的港口/公用设施；负例为军事基地、无来源坐标、损伤状态伪造。
- 授权负例：`display_allowed=false` 或 `screenshot_allowed=false` 的设施/引用进入 customer bundle/截图。
- 空数据样本：某 AOI/日期无记录时页面显示“无匹配/覆盖不足”，不填假点。
- API 失败样本：坏 bundle 只让当前专题 error，不拖垮 HIMARS 或 slow endpoint。

## 7. 脏数据与历史数据处理协议

### 7.1 默认原则

1. 所有外部输入只读，不在原目录覆盖、重命名、删除、转码或清理。
2. 不执行任何 `UPDATE/DELETE/ALTER/DROP`；本计划不写数据库。
3. 不自动纠正来源、身份、时间、速度、坐标、设施状态或许可；只生成标准化副本、质量码和隔离记录。
4. 优先让代码兼容和隔离坏记录；写 bundle/customer 路径 fail-fast。
5. `sample_internal`、`historical_telemetry`、`public_source`、`catalog_only` 必须显式区分。
6. customer 构建默认不消费 `sample_internal`、`license_unknown`、`rough_bbox` 或 `catalog_only` 的具体对象。

### 7.2 质量码

### 7.3 隔离记录

- 清理原始目录、外部 scratch、quarantine 或历史构建。
- 合并 PR/MR、修改 CI/CD/Jenkins/远端配置或切换历史镜像。

如果未来确需清洗历史数据或数据库，只在新计划中列候选 SQL、备份、回滚和验证 SQL；本计划不提供也不执行写 SQL。

## 9. Git、发布和记录要求

```bash
git status --short
git diff --check
git diff --cached --check
git diff --cached --stat
git -C "$GINTBROKER_ROOT" status --short
```
