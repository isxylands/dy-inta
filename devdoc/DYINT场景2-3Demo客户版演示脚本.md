# DYINT 场景 2/3 客户版演示脚本

日期：2026-07-09

适用范围：售前客户沟通、内部彩排和客户 PPT 抽取。本文只保留客户可理解的业务故事、画面顺序、主持人口径和演示边界；数据字段、目录结构、规则权重和工程分层回到 `devdoc/DYINT场景2-3Demo数据规则与补强方案.md`。

## 1. 一句话主线

当海峡传来袭击、封锁或设施受损传闻时，值班团队最怕的是在真假未明时错过准备窗口。这个 Demo 展示系统如何把新闻、船舶和航空轨迹、海事通告、卫星影像和火点证据合成一张可追溯判断单，告诉海事、港口和能源设施团队哪些航道、船舶和设施需要立刻复核、加强监测和提前准备。

演示定位是“航运安全、设施保护、多源验证和风险降级”，不是进攻性军事研判系统。

## 2. 客户现场压力

| 客户角色 | 现场压力 | 系统改变的动作 |
| --- | --- | --- |
| 海事值班主管 | 夜间收到油轮遇袭、封锁或拦截传闻，公开信息互相矛盾，船舶轨迹也有缺口 | 从零散新闻切换到证据矩阵，决定是否提升监测、通知相关方和调取二次确认 |
| 港口运营负责人 | 外海风险升高，担心船期延误、锚地拥堵、保险成本和靠泊调整 | 看见受影响航道、锚地、进近区和船舶清单，形成可解释的排班和通知依据 |
| 能源设施安保负责人 | 新闻称港口或能源设施受损，官方又称恢复，需要判断哪一处还要持续监测 | 从设施卡、影像、火点、运营状态和恢复任务中判断“支持、反驳、待确认” |

## 3. 演示画面顺序

| 时间 | 画面 | 主持人口径 | 客户应看到的价值 |
| --- | --- | --- | --- |
| 0-1 分钟 | 三类角色压力卡 | “今天要解决的是真假未明时如何少错判、早准备、可追溯。” | 这不是数据大屏展示，而是值班决策辅助 |
| 1-3 分钟 | 常态基线地图 | “先有常态，后面才能解释什么是异常或风险上升。” | 航道、锚地、港口进近区和常态交通有参照物 |
| 3-5 分钟 | 风险窗口时间线 | “系统不把单条信号当结论，而是组织为支持、反驳、待确认。” | 新闻、遥测和通告被放进同一时间线 |
| 5-7 分钟 | 证据矩阵和评分 | “每一次升级都能回到证据，也能看到哪些证据不足。” | 分数不是黑箱预测，而是证据组织方式 |
| 7-9 分钟 | 设施监测卡 | “设施目录只回答监测谁；损伤和恢复必须等多源证据。” | 设施、组件、事件证据和恢复证据被分开 |
| 9-11 分钟 | 二次确认任务和报告 | “系统输出的是提升监测、通知相关方、调取影像和报告归档。” | 不确定性被转成复核任务和保护性准备 |

## 4. 场景 2：航运安全风险上升与保护性准备

演示从常态基线开始，而不是从已知结果开始。系统先展示 2 月常态航道、锚地、港口进近区和交通画像，再切换到 4 月过渡窗口，证明同一关注区下的数据质量、区域边界和目标归属可解释。

随后进入 5 月下旬主窗口和 6 月上旬补充窗口。公开新闻、船舶轨迹、航空活动和海事通告被放入同一条时间线。系统不会把某一条新闻直接当事实，也不会把轨迹缺口直接当风险结论；它会把每条证据标成支持、反驳或待确认，并说明为什么当前只适合提升监测，或为什么需要调取卫星影像、火点和海事通告做二次确认。

客户最后看到的是一份保护性准备报告：受影响的航道和港口进近区、需要重点复核的船舶或设施、证据矩阵、不确定性、下一步监测任务和报告归档建议。

客户版术语统一使用：

| 内部底稿常用说法 | 客户版说法 |
| --- | --- |
| 袭击风险预警 | 航运安全风险上升 |
| 防卫准备 | 保护性准备 |
| 快艇集群接近 | 近距离小型船只活动候选 |
| 威胁信号 | 公开风险主张或风险信号 |
| 高风险处置 | 二次确认、提升监测和报告归档 |

## 5. 场景 3：能源设施持续监测与恢复验证方法演示

场景 3 是场景 2 的自然延伸：风险不一定只影响船舶，也可能外溢到港口、油库、炼厂、液化天然气码头、电力和海水淡化综合体。

当前客户版不承诺“已经证明某个设施受损或恢复”。在真实或高质量替代事件包冻结前，场景 3 只演示方法：系统如何建立设施卡，区分设施目录、组件、监测任务、事件证据和恢复证据；当新闻或通告提出受损主张时，系统如何用火点、影像变化、运营状态和靠泊活动做验证；当恢复声明出现时，系统如何继续观察后续影像和运营指标，而不是只凭“没有火点”就结束。

客户最后看到的是设施监测报告和持续监测任务：哪个设施、哪个组件、哪些证据支持或反驳、还缺什么证据、下一次看什么、由谁复核、什么时候可以退出持续监测。

## 6. 需要冻结的演示资产

| 资产 | 最低要求 | 客户价值 |
| --- | --- | --- |
| 场景 2 事件包 | 至少 1 个主事件窗口和 1 个补充窗口；每个窗口有证据矩阵和评分时间线 | 证明系统能按历史时间回放，而不是事后解释 |
| 场景 3 设施包 | 至少 1 个港口或能源设施；目录素材、监测任务、事件证据、恢复证据分栏 | 防止把静态图片误当成损伤或恢复证据 |
| 授权和脱敏清单 | 客户可见截图、数据点和引用均有展示许可、截图许可、脱敏规则和有效期 | 避免现场后补授权或返工 |
| 6 张固定画面 | 客户压力、基线地图、风险时间线、证据矩阵、设施卡、任务和报告 | 不看长文也能完成 8-12 分钟走查 |

## 7. 主持人降级话术

| 客户追问 | 建议回答 |
| --- | --- |
| “这是不是军事预警系统？” | “不是。这里展示的是航运安全、设施保护、多源验证和风险降级，只输出保护性准备和复核任务。” |
| “系统能不能直接判断袭击会不会发生？” | “不能直接承诺确定性预测。第一版分数用于组织证据和触发复核，生产版需要样本校准和误报率评估。” |
| “这些设施图片能证明受损吗？” | “不能。设施目录和图片只回答监测对象是谁，损伤和恢复必须依赖多时相影像、火点、运营状态和通告等证据。” |
| “如果证据互相矛盾怎么办？” | “系统保留反证，把结论降级为待确认，并生成二次确认任务，而不是把传闻包装成事实。” |
| “能不能给具体处置动作？” | “只给提升监测、通知相关方、调取影像、人工复核和报告归档这类保护性动作，不输出攻击或打击建议。” |

## 8. 客户版通过标准

- 8-12 分钟可以讲完，不依赖客户理解本体字段、目录结构或工程类名。
- 非技术同事 2 分钟内能复述：谁在现场承压、系统改变哪个动作、最终输出什么任务或报告。
- 每一次风险升级都有证据来源、可见时间、质量说明和支持/反驳状态。
- 客户可见素材已确认展示许可、截图许可、脱敏规则和有效期。
- 所有建议动作都是保护性、复核性或持续监测动作。
- 不出现精确打击目标、武器发射点推断、攻击方定位或进攻性行动建议。
