# 中文技术写作 skill 精简与消融记录

2026-09-06

本轮将 `clear-technical-writing-zh` 从研究论证导向的长规则集，改为按材料用途选择写法的通用写作技能。主文件由 7,649 字符、582 行减为 1,777 字符、49 行，减少约 77%；加上按需读取的五个正向样例，共 2,998 字符，仍比旧版减少约 61%。字符数包含空白和 Markdown 标记，不代表模型 token 数。

新版保留事实依据、术语一致、条件与承诺边界，取消重复检查、分数门槛、短语计数和固定段落形态。技术论证只是适用文种之一；总体设计、详细设计和需求规格说明分别保留视图、合同和规范性条目。少量排比与概括句按实际作用判断，不因句式本身删除。

## 两份样例带来的修正

本轮用 macOS `textutil` 读取两份材料的正文，检查目录以及建设条件、数据流程、架构设计、功能设计、接口和迁移等相关段落。仅分析文字与组织方式，未做版式评价，也未验证历史技术结论。

| 样例位置 | 值得保留的写法 | 对旧规则的修正 |
| --- | --- | --- |
| NHW 2.1.1「基于NHW现有的平台」 | 一句列清现有资源，为方案提供条件 | 不必每段补齐研究问题、方法和验证 |
| NHW 2.3.3「数据流程设计」 | 按用户访问、身份确认和身份传递解释关系 | 顺序连接词有实际作用，不能按词删除 |
| NHW 4.3.2.2「用户服务」 | “系统应把最近一次回应的评论放到评论列表的最上方” | 需求条目允许“系统应”，不改写成研究活动 |
| 概要设计第4章「系统架构设计」 | 总体、技术、数据、部署分别成节 | 章节可独立展开，不压成单一帽子段 |
| 概要设计 5.1.1.1「标准化显示模块」 | 从功能需求到功能设计，再到界面操作 | 功能清单和操作细节属于有效设计内容 |

两份样例并非逐句标准答案：其中也存在反复宣称“高效、先进”、重复结尾和宽泛承诺。参考文件只摘取能说明组织方法的片段，不复制业务内容或技术选型。短排比的正向示例另行新拟并明确标注，没有冒充样例原文。

原文件位于 [NHW方案建议书](../docstyle-example/NHW项目方案建议书-2007年5月.doc) 和 [概要设计](../docstyle-example/某领域智能认知决策生成系统概要设计-2025年1月.docx)。这两份文件本轮开始时即为未跟踪文件，本轮没有修改或提交它们。skill 中的节选可独立阅读，不强制每次打开原文件。

## 消融方法

先固定六个任务，再对旧规则逐组删除。T1、T2由样例相关段落缩编而来；T3至T6为补充的合成任务。各组使用相同输入，只读取指定变体，在临时目录生成完整正文与修改理由；没有访问生产系统或修改源文档。

V0、V1、V2由三个独立子代理各生成一次。V3由V2代理继续执行，新版由V0代理继续执行，均要求从头作答、不以旧输出为底稿。它们的上下文并未重置，所以后两轮不能视为完全独立盲测。所有结果由本轮主代理复核。

原始版本取自本轮修改前的 HEAD `10b5a6cdabc513bcd3d158271843bb06f9d528bb`，路径为 `.agents/skills/clear-technical-writing-zh/SKILL.md`。各变体按下表逐步删除，其他内容不变，便于从 Git 重建。

| 版本 | 相对于上一版的处理 | 字符数 |
| --- | --- | ---: |
| V0 | 完整旧版 | 7,649 |
| V1 | 删除「写作工作流」至「改写示例」之间的流程、清单和快速检测；删除「质量评分」及之后的 Codex 执行要求 | 5,598 |
| V2 | 删除「技术材料的基本写法」、规则12「少用系统应写技术研究」、「段落长短服从内容」和「技术研究文档的结构规则」 | 4,197 |
| V3 | 删除规则1至5，以及重复的「示例一：去掉口号链」 | 3,264 |
| 新版 | 将剩余重复规则重新合并，增加按文种选择写法及有条件保留修辞的原则；移除领域固定示例，加入正向参考 | 主文件1,777；参考1,221 |

新版不是单变量消融，而是依据消融结果和样例重建后的回归。不能把新版变化全部归因于某一条规则。

复核重点是事实与合同是否保持、文种深度是否适配、结构能否查阅、是否无端扩写，以及修辞取舍是否有依据。未使用旧版的100分自评，也未用词频代替质量判断。

## 观察结果及保留决策

| 检查项 | 实际输出 | 决策 |
| --- | --- | --- |
| 删除重复检查后是否丢约束 | V0至V3均保留T3的必填类型、状态码、不创建记录及空数组待定项，T5保留选型与性能未知项 | 未观察到重复流程的额外收益，删除重复层，保留一次内容检查 |
| 取消研究专用规则后是否降低必要深度 | V2、V3保留T2全部标题与功能／设计层次，T5仍写出了问题、方法和验证思路 | 研究写法改为文种提示；本轮未证明旧版必然误改所有设计材料 |
| 正常概括句能否得到保留 | V0至V2的T4均删除“先试点，再推广”，理由直接称其为口号；V3仍删除，但理由变为合并安排；新版保留了该句 | 单纯删除限制不足以稳定改变偏好，新增按语义作用判断的正向提示；删除该句本身不判为内容错误 |
| 需求是否被不必要地推演 | V0至V2在T1补写“按最近回应时间排序”，原文只规定最近回应项置顶；V3、新版未扩大到整张列表的排序合同 | 保留不以润色改变技术含义的约束；这是小样本观察，不能归因于修辞规则消融 |
| 单句任务是否被扩写 | 所有版本T6正文均为一句，只有“追查／追溯”等措辞调整 | 不再要求所有任务完整执行五阶段流程 |
| 新版补充题 | T7保留“不得自动重试”和超时待定；T8保留章节用途、反复出现的“归档”和不删除原始材料的边界 | 不设禁词、词频和通用主语黑名单，也不因去重复误删条件 |

新版八题在上述人工检查项上未发现需要修正的内容遗漏或新增合同。这个结果只支持当前精简版本可作为下一轮使用基线，不证明对所有文种普遍更优。样本数量少、每组仅一次生成、部分输入来自用于设计规则的正向样例、后两轮复用了代理上下文，均限制结论强度。详细设计与完整需求规格说明尚无用户提供的整篇正向样例，当前以合成合同和需求条目验证，不宣称已覆盖整篇交付质量。
