## 1. 结论先行

上一版把场景 2 主目标写成“信息降噪”，这个理解偏了。根据最新口径，场景 2 的主目标应是：

> 袭击预警与防卫准备：基于历史已知事件回放，验证系统能否在商船被袭或区域攻击前，从 AIS/ADS-B 异常、航母/战机动向、新闻报道和规则命中中提前形成风险上升信号。

信息降噪仍然需要，但它只是避免误报和维持证据质量的配套能力，不是场景 2 的主叙事。

场景 3 的主目标应是：

> 能源关键设施损伤监测：针对炼厂、油库、LNG、港口能源设施、电力/海水淡化综合体等重点区域，用卫星多时相和火点/热异常做损伤与恢复监测，作为场景 2 之后的补充演示。

对用户小结的判断：

1. **场景 2 以 5-6 月商船被袭/海峡摩擦历史样例做预警回放，是正确方向。** 适合用“新闻结果反推预警模型”的方式验证系统是否能在结果发生前看到风险信号，而不是声称系统已经能做真实未来预测。
2. **AIS 信号静默、坐标异常、商船/快艇接近、航母部署、战机/无人机/加油机/侦察机动向、新闻报道应共同入模。** 其中 AIS/ADS-B 和新闻是第一版最可用的数据，卫星影像应作为证据不足时的 L2 二次确认，不应一开始就作为唯一主证据。
3. **场景 3 应聚焦能源关键设施，不要泛化成所有基础设施。** 机场/数据中心/港口可以作为关联影响对象，但主演示最好选能源设施或港口能源设施，这样更贴近海湾客户的防护需求。
4. **历史已知事件回放策略合理。** 由于实时采集和外部接口不稳定，第一版 demo 应冻结 5-6 月样例数据，通过“已知结果 → 回看前兆 → 验证规则链”的方式展示动态本体多源分析能力。

需要明确的边界：

- 可以做“风险上升预警”“袭击可能性评分”“建议提升防卫/护航/监测等级”。
- 不应承诺精确预测袭击时间、袭击路径、武器发射点或攻击方意图。
- 不输出进攻性行动建议，不输出可用于打击的精确军事部署坐标。

推荐两条场景关系：

```text
场景 2：袭击预警与防卫准备
  历史新闻结果
    ← 回看前兆窗口
    ← AIS/ADS-B/新闻/规则/航母战机动向
    → 风险评分与防卫准备建议
    → 证据不足时调用卫星影像二次确认

场景 3：能源关键设施损伤监测
  重点能源设施 AOI
    → T0/T1/T2/Tn 卫星影像
    → 火点/热异常
    → 损伤/恢复/运行影响
    → 持续监测任务
```

## 2. 当前材料重新评估

### 2.1 主方案文档

`devdoc/DYINT四场景本体数据与分析方案.md` 中场景 2 原写法偏“区域安全事件信息降噪”。这个标题需要调整。

> 场景 2：商船袭击预警与区域防卫准备本体

场景 2 的关键问题应从“哪些消息可信”调整为：

- 当前区域是否正在从外交摩擦、军事部署、海空活动异常，演化到商船被袭或能源通道受威胁？
- 哪些商船、航道、锚地、港口进近区域处于风险上升窗口？
- 哪些 AIS/ADS-B 异常是前兆信号，哪些只是数据质量或常规活动？

### 2.2 海贝 AIS/ADS-B 大数据

上一轮海贝数据盘点已经形成这些关键结论：

- 原始 CSV 约 12GB、1.35 亿行，不能反复全表扫描。
- AIS 覆盖 2 月、5 月、6 月，但 AIS 文件存在跨月和重复，必须按 `IR_LASTTIME` 真实时间去重。
- AIS 可支撑船舶活动回放、长期低速/锚泊、航迹缺口、位置跳变、目的港变化、区域穿越。
- ADS-B 可支撑航空活动背景和前兆型旁证，但大文件中身份字段大量缺失，不能单独判断军机属性。
- 5 月、6 月窗口对场景 2 有价值，尤其 5 月 20-28 日、6 月 2-11 日。

对场景 2 的用法：

| 数据 | 用法 | 限制 |
| --- | --- | --- |
| 海贝 AIS 5-6 月 | 做商船/油轮/快艇/港口进近区域活动底座，提取静默、跳变、低速、快速接近、异常停留 | 需去重、身份补全、正式 AOI、不能把缺口直接等同“关闭 AIS” |

## 3. 推荐 demo 主线

### 3.1 场景 2：袭击预警回放

推荐事件窗口：

| 窗口 | 用途 | 现有材料 |
| --- | --- | --- |
| 2026-05-25 23:00 至 2026-05-28 02:00 | 主事件：商船/油轮被袭或遭拦截风险回放 | 新闻 5/26-5/28、AIS 快艇/油轮异常、ADS-B F-35/KC-135/RC-135/MQ-9 |
| 2026-06-08 22:00 至 2026-06-11 02:00 | 副事件：海峡冲突、封锁、油轮拦截回放 | 新闻 6/9-6/11、AIS 航母/巡逻艇/快艇、ADS-B F-35/AH-64/KC-135/RC-135/MQ-9 |
| 2026-02-24 至 2026-02-28 | 远期背景：航母部署、双航母、战机活动 | 新闻、AIS 航母/补给舰、ADS-B 支援机/F-35 |

演示流程：

1. 选择已知结果事件，例如 2026-05-28 油轮拦截/阿巴斯港交火样例。
2. 系统回看事件前 72 小时。
3. 动态本体加载对象：商船、快艇、航母、战机、无人机、海峡 AOI、新闻主张。
4. 规则引擎或派生层计算前兆：
   - 新闻报复警告。
   - 无人机/拦截报道。
   - 快艇集群高速出现。
   - 商船 AIS 坐标缺失/速度为 0 再出现。
   - F-35、KC-135、RC-135、MQ-9 同窗活动。
5. 系统生成 `AttackWarningEvent`，风险从低到中、高逐步上升。
6. 证据不足时创建 `ImageryVerificationTask`，请求卫星覆盖商船异常区域或能源设施 AOI。
7. 三级输出不是“预测必然袭击”，而是“防卫准备建议”：提升监测、护航/避险、通知海事/港口/能源运营方、等待二次确认。

### 3.2 场景 3：能源关键设施损伤监测

场景 3 不应与场景 2 抢主叙事。它是场景 2 的补充：

- 当袭击预警指向能源设施或港口能源码头时，系统进入设施监测模式。
- 当新闻声称某设施受损时，系统检查火点、影像变化和运营状态。
- 当官方声称恢复时，系统用 T2/T3/Tn 影像和运营指标验证。

演示流程：

1. 选择一个能源设施 AOI，例如炼厂、油库、LNG 码头、电力/海水淡化综合体。
2. 展示 T0 基线：设施组件、正常活动、历史火点基线。
3. 导入一条袭击/火灾/服务中断主张。
4. 检查 FIRMS 火点、热异常、烟羽或夜光变化。
5. 调取 T1/T2 影像，看是否存在损伤、活动下降、车辆/船舶减少。
6. 进入 T3/Tn 恢复监测，判断是否恢复运营。
7. 输出 `DamageAssessment`、`RecoveryEvidence`、`MonitoringTask`。

## 4. 动态本体演示方案

### 4.1 动态本体不负责所有计算

根据 `doops动态军事本体数据源挂接评估.md`，`doops-dev` 适合承接：

- 对象定义。
- 关系定义。
- 属性和标签。
- 规则配置。
- 规则命中记录。
- 证据治理。
- 对象/关系入图。

但当前 doops 规则能力不适合直接计算：

- 地理围栏。
- 距离。
- 时间窗口。
- 轨迹聚合。
- 多目标接近。
- AIS/ADS-B 消失再出现。
- 多源时序相关性。

因此第一版演示架构应是：

```text
数据层
  新闻 / AIS / ADS-B / 卫星 / 火点 / AOI
    ↓
派生计算层
  去重、时间窗、距离、轨迹异常、快艇接近、航空活动增强
    ↓
动态本体层 doops
  对象、关系、规则元数据、规则命中、证据链、报告对象
    ↓
展示层 gintbroker 或 demo UI
  地图、时间轴、证据矩阵、预警卡、设施监测卡、报告
```

### 4.3 核心关系

| 关系 | 主体 → 客体 | 推理价值 |
| --- | --- | --- |
| `located_in` | 船舶/航空器/新闻主张/设施 → AOI | 把观测归到海峡、港口、能源设施 |
| `near` | 快艇/商船/火点/影像变化 → 设施或航道 | 判断潜在影响 |
| `claims` | 新闻来源 → 新闻主张 | 保留来源说法 |
| `precedes` | 前兆信号 → 结果事件 | 做历史回放和模型验证 |
| `supports` | AIS/ADS-B/新闻/卫星 → 预警事件 | 提升风险评分 |
| `refutes` | 无火点/无影像变化/官方否认 → 主张 | 降低置信度 |
| `triggers` | 预警事件 → 卫星任务/报告/持续监测 | 打通工作流 |
| `affects` | 预警/损伤事件 → 商船/航道/能源设施 | 输出防卫对象 |
| `changed_from` | T1/T2/T3 影像 → T0 基线 | 做损伤/恢复 |

### 4.4 预警规则

第一版显式规则即可，不必一开始训练模型。

| 规则 | 输入 | 触发 | 输出 |
| --- | --- | --- | --- |
| `R-WARN-001 新闻威胁升级` | 新闻主张 | 72 小时内出现官方警告、报复、无人机、油轮拦截、海峡封锁等 >= 2 类 | `ThreatSignal` |
| `R-WARN-002 快艇集群接近` | AIS | 同一 AOI 内 >= 3 艘快艇高速出现，距离商船/航道小于阈值 | `TelemetryAnomaly` |
| `R-WARN-003 商船 AIS 异常` | AIS | 商船在高风险 AOI 出现坐标缺失、速度异常、长时间无更新、静默后再出现 | `TelemetryAnomaly` |
| `R-WARN-004 航空支撑增强` | ADS-B | 侦察/加油/战机/无人机在同一窗口内出现或活动增强 | `ThreatSignal` |
| `R-WARN-005 航母部署支撑` | AIS/ADS-B/新闻 | 航母、补给舰、战机部署新闻与遥测同窗 | `StrategicPostureSignal` |
| `R-WARN-006 多源同窗升级` | News + AIS + ADS-B | 24-72 小时内新闻威胁、AIS 异常、ADS-B 支撑活动同时出现 | `AttackWarningEvent` 风险升高 |
| `R-WARN-007 证据不足请求卫星` | 预警事件 | 风险高但缺火点/影像/官方确认 | `ImageryVerificationTask` |

风险评分建议：

```text
base = 0
新闻威胁升级 +20
多源新闻一致 +10
快艇集群接近 +25
商船 AIS 异常 +20
航空支撑增强 +15
航母/支援部署 +10
官方或海事通告支持 +20
卫星/火点支持 +20
证据矛盾 -20
数据质量不足 -10
```

阈值：

- `0-29`：背景关注。
- `30-49`：风险上升。
- `50-69`：建议提升监测和防卫准备。
- `70+`：建议启动二次确认和高层简报。

### 5.3 防止“未来信息泄露”

历史回放最容易犯的错误是把结果发生后的新闻拿来当发生前预警信号。必须把数据分成：

| 类型 | 用法 |
| --- | --- |
| `pre_event_signal` | 结果发生前可见，允许用于预警 |
| `event_result` | 结果事实，只用于评估，不参与提前评分 |
| `post_event_confirmation` | 结果后的确认报道，只用于验证模型是否命中 |
| `background_context` | 背景信息，低权重 |

每条新闻和遥测点都要有 `visible_at`。预警评分只能使用 `visible_at <= scoring_time` 的证据。

## 7. 验收口径

### 7.1 场景 2

| 验收项 | 最低标准 |
| --- | --- |
| 历史事件回放 | 至少 1 个 5 月事件、1 个 6 月事件 |
| 前兆窗口 | 每个事件至少回看 24-72 小时 |
| 多源证据 | 每个事件至少有新闻 + AIS + ADS-B 三类证据中的两类 |
| 预警评分 | 能展示结果发生前分数逐步上升 |
| 防未来信息泄露 | 评分时间点不能使用结果后的证据 |
| 二次确认 | 至少 1 条高风险但证据不足事件触发卫星任务 |
| 输出 | 生成防卫准备报告，不输出进攻建议 |

| --- | --- |
