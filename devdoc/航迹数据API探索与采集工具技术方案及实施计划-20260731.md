## 1. 结论

推荐在 `/Users/liushen/Documents/githubDevs/dy-track-explorer` 新建独立本地 Git 仓，采用 **Go 模块化单体 + React 单页应用**。`dy-inta` 继续只保存需求、调研、Mock、方案和执行记录，不承载运行代码。Go 负责上游认证、token 复用、请求校验、ADS-B/AIS 调用、自适应时间切片、去重、诊断和指标；React 负责 API 探索工作台及后续管理页面。生产构建将前端静态资源嵌入 Go 二进制，形成一个进程、一个端口、一个部署单元。远端仓、CI 和外部制品发布在实际首次使用前按需准备，不阻断本地 T0～T3。

前端选用 `React + TypeScript + Vite + Ant Design + React Router + TanStack Query`。这套组合适合数据密集型工具，也能自然扩展任务、运行记录、存储、配置和监控页面。当前原型的深色视觉、三栏工作台和字段联动保留为定制业务组件，不改造成通用后台卡片页。

后端基于 Go 标准库 `net/http`，不引入 Gin、Fiber 或微服务框架。当前接口数量和中间件复杂度不需要额外 Web 框架；认证管理、上游访问、查询执行、字段目录和 HTTP API 按包隔离。后续调度与存储作为同一进程内的新模块接入，共用查询执行器，不复制采集逻辑。

首期不实现周期任务和业务数据持久化，但架构必须支持两种查询模式：

- `direct`：严格执行一次上游调用，用于看清实际请求、响应、字段和错误。
- `complete`：把当前查询时间窗切到单片不超过一页，按本次响应中的 `id` 去重，返回带 `completeness=best_effort` 的尽力结果。它用于规避普通翻页的确定性缺陷，也作为后续周期任务的执行内核，但不表示上游历史快照权威完整。

本方案风险等级为**标准**。首期只有外部只读调用，不写业务数据库。Go 服务持有上游凭据并返回原始航迹数据，因此即使默认只监听回环地址，也必须在 HTTP 入口校验 `Host` 和浏览器 `Origin`，防止恶意网页借 DNS rebinding 调用本地凭据代理。提供方当前仅暴露明文 HTTP，这是使用方无法在本项目内修复的外部限制；本方案只客观记录该事实，不要求使用方改造提供方，也不再为此设置确认人、网络范围、有效期或其他重复授权 Gate。未来启用本地存储后，数据留存、磁盘容量、备份和迁移升级为高风险项，在进入该阶段前执行文中最小 Gate。

## 2. 目标、成功标准与边界

### 2.1 首期目标

1. 把已确认的 HTML Mock 实现为可长期维护的真实 Web 应用。
2. 浏览器不接触上游用户名、密码和 token，由 Go 后端统一认证和调用。
3. 用户能在一个工作台内同时看到中文参数解释、英文字段、实际请求、原始响应、样本值和字段备注。
4. ADS-B 与 AIS 都能完成真实小范围查询，明确展示 HTTP 状态、业务 `code`、`requestid`、耗时、响应大小、分页信息和字段质量提示。
5. 尽力查询模式不使用普通 `pageNum++` 遍历，采用时间切片和本次结果集内的 `id` 去重，并显式说明上游历史可能补录或重整。
6. 工程结构允许后续增加任务、运行记录、本地数据、监控和设置页面，不重写首期查询链路和应用壳。

### 2.2 可判定成功标准

| 编号 | 成功标准 | 通过条件 |
| --- | --- | --- |
| S1 | 原型主链路实现 | ADS-B/AIS、参数编辑、请求预览、响应高亮、字段联查、筛选、复制和代码生成可用 |
| S2 | 真实上游闭环 | 使用受控小样本完成两类真实查询；前端展示内容与 Go 捕获的脱敏请求、上游 JSON 一致 |
| S3 | 应用层秘密与本地代理边界收敛 | 浏览器网络响应、页面、日志、错误信息和 Git 中不出现用户名、原始密码或 token；非法 `Host`/`Origin` 在调用上游前返回 403；不把该判定扩写成上游传输安全 |
| S4 | 错误语义正确 | HTTP 非 2xx、业务非 `200`、业务 `604`、超时、单片响应过大、complete 聚合结果过大和 JSON 异常分别可判定；`604` 最多刷新并重放一次 |
| S5 | 尽力查询语义准确 | fake 上游构造 `totalPages > 1` 时自动二分；单秒仍超 1000 条时明确失败；结果按本次响应中的 `id` 去重；记录数或聚合字节超限时 fail-fast；页面始终显示 `best_effort` 和永久历史可变警告 |
| S6 | 可扩展前端 | 新增一个测试路由和页面模块不需要修改探索页内部组件；导航、路由、权限占位和 API 客户端有固定入口 |
| S7 | 可交付运行 | 前后端测试通过；前端可嵌入 Go；单二进制或容器启动后健康检查、页面和 API 均可访问 |
| S8 | 可观测 | 每次调用有 `query_id`、结构化日志和基础指标；不记录敏感 header 或完整登录 URL |

### 2.3 本轮不做

- 不实现周期任务、任务持久化、业务数据落表和数据清理。这些不影响首期真实探索闭环，按第 8 节触发后续增量。
- 不开发自有用户账号、密码和权限系统。首期默认本机或受信内网使用，但 `Host`/`Origin` 校验仍是必需的服务端边界；多人访问时接现有 OIDC/SSO。
- 不把该 API 解释为唯一事实源，不自动给出事件归因、航班运行结论或船舶真实穿越结论。
- 不把地图回放设为首屏主功能。空间展示仍是辅助视图，必须建立在字段、时间和点位密度已经看清的前提上。
- 不提前拆微服务，不引入消息队列、分布式调度、服务注册或 Kubernetes 专属逻辑。

## 3. 已确认事实与核心问题

### 3.1 已确认事实

| 类型 | 事实 | 对方案的影响 |
| --- | --- | --- |
| 仓库 | `dy-inta` 是文档工作区，没有 Go、Node、CI 或运行工程 | 运行代码落在独立 `dy-track-explorer` 仓；本仓只保留方案与执行证据 |
| 认证 | 登录使用时间戳与两次 MD5，业务请求使用 `TRSDH-Access-Token` | 凭据和 token 只能留在 Go 进程；需要 token 缓存与单次刷新重放 |
| 成功判定 | 未登录时可能 HTTP 200、业务 `code=604` | 后端和前端都不能只看 HTTP 状态 |
| 查询 | ADS-B/AIS 参数结构相近，对象字段分别为 `icao`、`mmsi` | 共享查询模型，数据集目录负责差异字段和端点映射 |
| 时间 | `endLoadTime` 实测表示结束入库时间；时间字段时区未说明 | 保留原始字符串；字段目录明确实测/待确认状态，不擅自转 UTC |
| 分页 | 单页上限 1000；历史分页总数和内容不稳定 | 尽力查询按时间切片，不使用普通翻页采全量，也不承诺权威完整 |
| 容量 | 未公布限流；当前建议单 worker | 首期并发上限默认为 1，可配置但不能由前端任意放大 |
| 数据质量 | 部分字段单位、来源和覆盖质量未知 | 字段目录和响应诊断必须呈现不确定性，不能在 UI 中补造字段 |
| 传输 | 提供方当前仅有明文 HTTP，使用方不能修改提供方 | 应用不宣称链路安全；上游 client 默认禁用 ambient proxy；真实调用使用显式配置，不增加使用方确认流程 |
| 浏览器入口 | 回环服务仍可能被 DNS rebinding 指向，浏览器同源策略不能替服务端识别可信来源 | HTTP 入口必须限制 `Host`，校验非空 `Origin`，不启用 CORS；非法来源不得进入上游 client |
| 历史可变性 | 同一历史窗口可能因后补或重整而变化 | `complete` 只能表示当次尽力结果；稳定采集依赖后续水位线、重叠回看和持久化核对 |
| 标识 | `id` 只在当前样本内确认唯一，跨任务长期稳定性未知 | 首期仅用于本次内存去重；长期唯一约束必须通过 M1 Gate |
| 原型 | 用户已确认“参数、请求、响应、字段对照同屏”的新版原型 | React 实现以该信息架构为验收基准，不回到多 Tab 或地图优先结构 |

### 3.2 核心问题

1. **调用链包含凭据和不透明业务错误。** 浏览器直连会泄露凭据，也无法集中处理 token、超时、重试和业务码；改为本地 Go 代理后，还必须阻断恶意 `Host`/`Origin`，不能依赖浏览器同源策略防 DNS rebinding。
2. **“看见 JSON”不足以理解 API。** 参数、字段、实际值和说明必须由稳定字段目录关联，不能散落在前端常量和后端结构体中各维护一份。
3. **直接调用与尽力采集的行为不同。** 探索时要保留真实单次响应；尽力查询需要切片、去重和记录执行摘要，但一次查询无法证明动态历史没有后补或重整。两条路径共享底层客户端，同时必须区分结果语义。
4. **后续页面会快速增加。** 单文件 HTML、全局状态和手写 DOM 更新无法承载任务、运行记录、存储和监控。
5. **本地持久化会改变运行风险。** SQLite 适合单机，但不适合网络文件系统和多写入实例；存储开关、留存和备份必须在进入存储阶段前确定。

## 5. 推荐架构

### 5.1 运行结构

```mermaid
flowchart LR
  U["浏览器\nReact SPA"] -->|"同源 /api/v1"| H["Go HTTP API"]
  H --> C["字段目录 Catalog"]
  H --> E["查询执行器 Explorer Runner"]
  E --> D["TRS DH Client\n认证、token、重试、限流"]
  D --> X["外部 ADS-B / AIS API"]
  E --> O["结构化日志与指标"]
  J["周期任务模块\n后续"] -.调用同一 Runner.-> E
  E -.可选 Sink.-> S["SQLite / PostgreSQL\n后续"]
  H -->|"go:embed"| W["internal/webassets/dist"]
```

Go 是唯一持有上游秘密的信任边界。进入路由前先执行 `Host`/`Origin` guard；前端不能提交上游 URL、登录参数、header 名和值，也不能选择任意目标地址。`dataset=adsb|ais` 由后端映射到固定端点，避免工具演变成通用 HTTP 代理或 SSRF 入口。

运行代码、测试、本地构建配置和制品定义只存在于独立 `dy-track-explorer` 仓；本方案文档继续留在 `dy-inta`。两仓不复制秘密或生成物，实施仓 README 反向链接本方案和 API 调研文档。

### 5.2 技术选型

基线版本以 2026 年 7 月 31 日的官方稳定版本为准；实施时把准确 patch 版本写入 `go.mod`、`package-lock.json` 和构建镜像，不使用浮动 `latest`。

| 层 | 选择 | 基线 | 选择理由 |
| --- | --- | --- | --- |
| 后端语言 | Go | 1.26.x | 标准库覆盖 HTTP、JSON、嵌入资源、并发与测试；适合长期单进程采集服务 |
| HTTP | `net/http`、`http.ServeMux` | Go 标准库 | 路由规模小，减少框架依赖；中间件自行保持薄层 |
| 前端 | React + TypeScript | React 19.2 | 组件和状态边界适合多页面数据工具；生态覆盖路由、表格、查询和测试 |
| 构建 | Vite | 8.1 | 纯 SPA 无需 SSR；开发反馈快，生产产物可直接嵌入 Go |
| Node | Node.js | 24 LTS | 当前 LTS；满足 Vite 8 要求，避免使用 Current 或 EOL 版本 |
| UI | Ant Design | 6.5 | 企业应用表单、表格、布局、反馈和主题能力完整；保留定制工作台样式 |
| 路由 | React Router | 8.3 | 明确管理 Explorer、Tasks、Runs、Storage、Monitoring、Settings 路由 |
| 服务端状态 | TanStack Query | 当前稳定版 | 处理请求、缓存、失效、轮询和后台刷新；后续监控页可直接复用 |
| JSON 展示 | CodeMirror 6 | 当前稳定版 | 请求/响应高亮、折叠、搜索和字段定位；比 Monaco 更轻 |

### 5.5 上游调用链

```text
Host / Origin guard
  → Host 必须命中当前部署的精确 allowlist
  → 非空 Origin 必须精确等于 PUBLIC_ORIGIN
  → 失败返回 403，不进入 handler 和上游 client
HTTP handler
  → 请求 DTO 校验
  → dataset allowlist 映射
  → Explorer Runner
      → direct：调用一个时间片
      → complete：单页探测 → 超页二分 → id 去重
  → TRSDH Client
      → token 未到刷新点：复用
      → token 缺失/到期：互斥登录
      → 业务 604：清空 token，刷新一次并重放
      → 网络/502/503/504：最多 3 次带抖动退避
  → 捕获脱敏请求、原始 JSON、执行摘要和诊断
```

关键约束：

- 默认 `max_concurrent_queries=1`，并发上限只能由服务端配置调整。
- `Host` guard 位于 HTTP 中间件最外层并覆盖静态资源、健康检查和 `/api/v1`；`Origin` guard 覆盖 `/api/v1`。两者都在任何上游调用之前执行，拒绝响应不回显收到的 Host/Origin。
- 连接超时 5 秒，单请求总超时 40 秒；尽力查询另设任务级 deadline。
- 响应使用 `io.LimitReader`，默认上限 20 MiB；超过上限明确返回 `UPSTREAM_RESPONSE_TOO_LARGE`。
- Go 默认 transport 自动处理 gzip，不手工设置 `Accept-Encoding`。
- 上游 client 从 `http.DefaultTransport` clone 后显式设置 `Transport.Proxy=nil`，不继承 `HTTP_PROXY`、`HTTPS_PROXY` 或 `NO_PROXY`。首期不支持上游代理；现场确需代理时另行增加显式单一配置和测试，不能静默恢复 `ProxyFromEnvironment`。
- token 提前在 100 分钟刷新；刷新采用互斥锁和二次检查，防止并发登录。
- 日志只记录 endpoint 枚举、参数摘要、状态、耗时和 request ID，不记录 token、密码摘要或完整登录 URL。
- 当前上游 `http://` 由 `TRSDH_ALLOW_INSECURE_HTTP=true` 显式启用；未设置时客户端拒绝明文地址。该开关只表达提供方接口现状，不能把 HTTP 变安全，也不触发额外人工确认流程。

### 5.7 HTTP API 契约

#### `GET /api/v1/catalog`

返回可用数据集、固定端点标识、请求参数、返回字段、中文说明、数据类型、单位和确认状态。前端不内置第二份字段字典。

确认状态使用有限枚举：

- `documented`：文档明确。
- `observed`：实测确认，例如 `endLoadTime`。
- `unknown`：单位、时区、来源或生成逻辑待确认。
- `unavailable`：接口不返回。

#### `POST /api/v1/explorer/queries`

请求体共用数据集和参数，但响应由 `mode` 明确分支。OpenAPI 3.1 使用 `oneOf` 和 `mode` discriminator 生成互斥类型，前端不能靠字段是否存在猜测模式。

请求示例：

```json
{
  "dataset": "adsb",
  "mode": "direct",
  "parameters": {
    "startPubTime": "20260729053000",
    "endPubTime": "20260729060000",
    "minLon": 34.0,
    "minLat": 29.0,
    "maxLon": 40.0,
    "maxLat": 34.0,
    "pageNum": 0,
    "pageSize": 1000,
    "sorts": "loadTime"
  }
}
```

服务端拒绝未知顶层字段、未知数据集、任意 URL、`pageSize > 1000`、非法日期、反向时间窗和越界坐标。时间合同固定如下：

- `direct` 的起止时间必须精度一致，允许 `yyyyMMdd` 或 `yyyyMMddHHmmss`；校验为真实日期后原样发送，实际请求预览与发送值完全一致。
- `complete` 的起止时间只允许 14 位 `yyyyMMddHHmmss`，因为切片算法按秒计算；8 位日期直接返回 `INVALID_TIME_PRECISION`，不在后端隐式扩展成全天。
- `direct` 允许用户查看分页行为；`complete` 要求 `pageNum=0` 并自行切片。

#### `direct` 成功响应

`direct` 只执行一次上游请求，返回该次 transport、业务状态和未经改写的原始 `upstream.body`。它不返回 `completeness`。

```json
{
  "queryId": "01J...",
  "mode": "direct",
  "request": {
    "method": "POST",
    "endpoint": "/base/osint/aircraft/adsb/list",
    "headers": {
      "Content-Type": "application/json",
      "TRSDH-Access-Token": "***"
    },
    "body": {
      "startPubTime": "20260729053000",
      "endPubTime": "20260729060000",
      "pageNum": 0,
      "pageSize": 1000
    }
  },
  "transport": {
    "httpStatus": 200,
    "durationMs": 286,
    "responseBytes": 6963,
    "retryCount": 0,
    "tokenRefreshed": false
  },
  "upstream": {
    "businessCode": "200",
    "message": "",
    "requestId": "...",
    "body": {}
  },
  "analysis": {
    "recordsReceived": 22,
    "warnings": []
  }
}
```

`upstream.body` 使用 `json.RawMessage` 保留这一请求的上游 JSON。Go 只剔除敏感 header，不改写字段值。

#### `complete` 成功响应

`complete` 是多次上游请求的本地合并结果，不包含伪造的单一 `transport`、`upstream.requestId` 或 `upstream.body`。每个切片只返回排查所需摘要，合并记录放在 `result.content`。

```json
{
  "queryId": "01J...",
  "mode": "complete",
  "query": {
    "method": "POST",
    "endpoint": "/base/osint/aircraft/adsb/list",
    "parameters": {
      "startPubTime": "20260729053000",
      "endPubTime": "20260729060000",
      "pageSize": 1000
    }
  },
  "result": {
    "queriedAt": "2026-07-31T15:30:12+08:00",
    "completeness": "best_effort",
    "requestCount": 3,
    "acceptedSliceCount": 2,
    "recordsReceived": 23,
    "uniqueIds": 22,
    "duplicateCount": 1,
    "content": [],
    "slices": [
      {
        "start": "20260729053000",
        "end": "20260729060000",
        "decision": "split",
        "httpStatus": 200,
        "businessCode": "200",
        "requestId": "...",
        "durationMs": 241,
        "responseBytes": 20143,
        "retryCount": 0,
        "tokenRefreshed": false,
        "recordsReceived": 1000,
        "totalPages": 2
      },
      {
        "start": "20260729053000",
        "end": "20260729054459",
        "decision": "accepted",
        "httpStatus": 200,
        "businessCode": "200",
        "requestId": "...",
        "durationMs": 214,
        "responseBytes": 4012,
        "retryCount": 0,
        "tokenRefreshed": false,
        "recordsReceived": 12,
        "totalPages": 1
      },
      {
        "start": "20260729054500",
        "end": "20260729060000",
        "decision": "accepted",
        "httpStatus": 200,
        "businessCode": "200",
        "requestId": "...",
        "durationMs": 226,
        "responseBytes": 3790,
        "retryCount": 0,
        "tokenRefreshed": false,
        "recordsReceived": 11,
        "totalPages": 1
      }
    ],
    "warnings": [
      {
        "code": "UPSTREAM_MUTABLE_HISTORY",
        "message": "上游历史可能补录或重整，本结果不是权威完整快照"
      }
    ]
  }
}
```

`slices[]` 按实际上游请求顺序记录探测和最终切片；`decision=split` 的响应只用于决定继续二分，不计入合并 `recordsReceived/content`，`decision=accepted` 才进入最终去重结果。这样每次上游请求及其 `requestid` 都可排查，同时不会把探测页重复混入结果。

`complete` 采用 fail-fast：任一必要切片在允许重试后仍失败，整次请求返回统一错误 `COMPLETE_SLICE_FAILED`，`details` 只包含失败切片范围、HTTP/业务码、`requestid`、错误摘要和已完成切片数，不返回部分 `content`。单秒仍超过上限时返回 `SLICE_DENSITY_EXCEEDED`。首期不增加 `partial` 成功状态。

`complete.result.completeness` 永远为 `best_effort`，并永久返回 `UPSTREAM_MUTABLE_HISTORY`；T4 重跑结果是否一致都不能升级完整性等级。为防止服务端和浏览器内存失控，首期同时限制尽力查询最大唯一记录数和完整响应 JSON 字节数，默认分别为 20,000 和 20 MiB：

- 只有 `decision=accepted` 且去重后准备进入 `result.content` 的记录才计入聚合预算；每条记录先做 JSON 编码并累计字节，下一条会超限时立即返回 `COMPLETE_RESULT_TOO_LARGE`。`decision=split` 的探测内容解析后即丢弃，不进入合并结果或字节预算。
- 成功 DTO 在写 HTTP status/header 前，先编码到上限为 `MAX_COMPLETE_BYTES + 1` 的受限缓冲区；包含 `slices[]` 和其他元数据的最终 `CompleteQueryResponse` 仍超限时返回同一错误。错误响应不包含部分 `content`。
- `MAX_COMPLETE_RECORDS` 与 `MAX_COMPLETE_BYTES` 任一先达到都 fail-fast，并提示缩小时间/空间范围。后续大批量采集不经浏览器返回全量，直接进入可选持久化 sink。

### 5.8 配置与安全边界

首期配置：

```text
TRSDH_BASE_URL
TRSDH_USERNAME
TRSDH_PASSWORD
TRSDH_ALLOW_INSECURE_HTTP=true
LISTEN_ADDR=127.0.0.1:8080
PUBLIC_ORIGIN=http://localhost:8080
REQUEST_TIMEOUT=40s
COMPLETE_QUERY_TIMEOUT=5m
MAX_RESPONSE_BYTES=20971520
MAX_COMPLETE_RECORDS=20000
MAX_COMPLETE_BYTES=20971520
MAX_CONCURRENT_QUERIES=1
LOG_LEVEL=info
```

- 用户名和密码只从环境变量或 secret mount 读取，不进入配置页面、SQLite、前端 bundle 或诊断导出。
- `TRSDH_BASE_URL` 由部署者配置，浏览器不能修改。
- `TRSDH_ALLOW_INSECURE_HTTP` 默认 `false`；当前提供方仅支持 HTTP 时由部署者显式设为 `true`。服务启动日志只记录“已启用明文上游”的布尔状态，不记录完整登录 URL、凭据摘要或 token。
- 上游 `http.Client` 明确禁用环境代理；即使进程环境存在 `HTTP_PROXY`、`HTTPS_PROXY` 或 `NO_PROXY` 也不得改变请求路径。首期配置不提供 proxy URL，避免出现未验证的第二分支。
- API 只接受预定义数据集和参数；所有响应设置 `X-Content-Type-Options: nosniff` 和合理 CSP。首期不启用 CORS，不返回 `Access-Control-Allow-Origin`；浏览器同源策略只作为补充，不能替代服务端 guard。
- 首期默认 `LISTEN_ADDR=127.0.0.1:8080`。在回环监听模式下，Host allowlist 固定为同一监听端口上的 `localhost`、`127.0.0.1` 和 `[::1]`，不接受后缀匹配、通配符、其他 IP 表示或任意端口；`PUBLIC_ORIGIN` 未设置时规范化为 `http://localhost:<listen-port>`。浏览器应从该 canonical origin 打开应用；合法 Host 且无 `Origin` 的 CLI/cURL 请求可以通过。
- 非空 `Origin` 必须在规范化后精确等于 `PUBLIC_ORIGIN` 的 scheme 与 authority；`null`、userinfo、path、query、fragment、通配符和列表值全部拒绝。API 不因请求缺少 `Origin` 就推断它来自浏览器，安全性由 Host allowlist 与浏览器无法自定义 Host 共同保证。
- 容器或反向代理使用 `LISTEN_ADDR=:8080`、`0.0.0.0:*`、`[::]:*` 或其他非回环地址时，必须显式配置唯一 `PUBLIC_ORIGIN`，否则启动失败；此时 Host allowlist 只取该 origin 的精确 authority。反向代理必须把 Host 覆盖/保留为该 authority，并先完成现有认证；后端不读取 `Forwarded`、`X-Forwarded-Host`、`X-Forwarded-Proto` 或其他客户端可伪造 header 来扩展信任。
- Host/Origin guard 在静态资源和 API handler 之前执行；非法 Host，或 `/api/v1` 上不匹配的非空 Origin，返回 403 且不调用上游。配置解析测试必须覆盖 IPv4、IPv6、显式端口、默认端口、非回环缺配置和非法 origin。
- `MAX_RESPONSE_BYTES` 限制每次上游响应；`MAX_COMPLETE_RECORDS` 与 `MAX_COMPLETE_BYTES` 分别限制 complete 的唯一记录数和最终完整响应 JSON。三者均须为正数；complete 任一聚合上限超出都返回 `COMPLETE_RESULT_TOO_LARGE`，不返回部分结果。
- 不为当前限制新增自建 TLS 隧道、VPN 或提供方改造任务；若部署环境已有受控专线/VPN，应优先使用，但不把它伪装成应用层 TLS。提供方未来开放 HTTPS 后，切换到证书校验通过的 HTTPS 并关闭 insecure 开关。
- 需要多人访问时，在部署前接现有 OIDC/SSO 或反向代理认证。不得自行实现弱口令登录页。
- 原始响应可能包含敏感航迹信息。诊断导出默认脱敏并需要用户主动操作；不得自动上传到第三方服务。

## 7. 关键未知项与最小 Gate

只有表中明确标记为 Gate 的条目才阻断对应时点。提供方明文 HTTP 不要求本项目整改，也不再作为 T4 Gate；应用侧已经通过 `Proxy=nil`、Host/Origin guard、日志脱敏和低频只读查询控制自身可控边界。

| 类型 | 未知项或约束 | 为什么改变方案 | 默认分支 | 验证时点与 Pass | Fail 分支 |
| --- | --- | --- | --- | --- | --- |
| T0 Gate | 本地目标路径状态 | 防止覆盖既有目录或嵌套错误 Git 根 | 固定本地路径建立独立 Git 仓 | 路径不存在或为空，初始化后 `git rev-parse --show-toplevel` 等于目标路径 | 路径非空或属于其他 Git 根则停止并请求处理；不得落回 `dy-inta` |
| 首次外部写 Gate | 远端、PR 和 CI 权限 | 只影响 push/CI，不影响本地开发验证 | 继续本地 commit 和 `make verify` | 用户明确授权且远端/权限可用后再 push；CI 调用同一 `make verify` | 不 push，不创建占位权限文件；本地阶段可继续 |
| 发布 Gate | 外部制品目标与写权限 | 只影响外部分发，不影响本地二进制/镜像 | T3 先生成本地制品和 SHA-256 | 用户要求发布时再确认目标与写权限 | 保留本地制品，不宣称已发布 |
| 部署 Gate | 工具是否只在本机/受信内网使用 | 决定是否需要用户认证；不改变 Host/Origin guard 的必选性 | 回环地址使用固定 allowlist；反向代理使用唯一显式 `PUBLIC_ORIGIN` | 非回环监听已配置精确 origin、代理 Host 和现有认证；恶意来源测试通过 | 缺 `PUBLIC_ORIGIN` 时服务拒绝启动；缺认证时不开放多人访问，不自建密码体系 |
| M1 Gate | 后续是否单实例且数据库位于本地文件系统 | 决定 SQLite 是否适用 | 单实例 SQLite WAL | M1 前确认一个写进程、本地磁盘、无需 HA | PostgreSQL；不得把 WAL 数据库放 NFS |
| M1 Gate | 数据许可和留存期限 | 决定能否保存 Raw、保存多久 | 首期不持久化业务数据 | M1 前取得允许落盘的范围、目录权限和期限 | 只保留执行摘要，Raw/Normalized sink 禁用 |
| M1 Gate | `id` 是否跨日期、跨重跑窗口稳定 | 决定能否作为长期唯一键 | 首期仅做单次结果集内存去重 | ADS-B/AIS 分别统计同 ID 的对象、时间、坐标与内容变化，并通过冲突 fixture | 不设 `UNIQUE(dataset, source_id)`；使用追加版本和冲突记录，待验证复合键 |
| M1 Gate | 上游可接受并发和频率 | 决定调度吞吐 | 1 worker、低频 | M1 试运行期间 P95、错误率和服务方反馈均稳定 | 保持单 worker、扩大时间窗或降低任务频率 |
| M1 Gate | 时间字段时区 | 决定标准化时间列 | 原始字符串 + UTC 为空 | M1 前取得服务方说明并用样本核对 | 继续保留原值，不生成伪 UTC |

SQLite WAL 只用于单机本地文件系统。官方文档明确指出 WAL 依赖同机共享内存，不适合网络文件系统：[SQLite Write-Ahead Logging](https://www.sqlite.org/wal.html)。

## 8. 后续扩展设计

### 8.1 周期任务

进入 M1 后增加 `internal/jobs`，任务配置包含：

- 名称、数据集、Cron 表达式、明确时区、启停状态。
- 观测范围、入库水位线、重叠分钟数、回看周期。
- 执行模式固定为 `complete`，但结果语义仍为 `best_effort`；可恢复采集依赖水位线、重叠回看和持久化核对。
- 保存策略：`none`、`raw`、`normalized`、`raw_and_normalized`。
- 单次 timeout、最大记录数、失败后重试次数。

手工查询和周期任务都调用 `explorer.Runner`。调度器只负责触发、互斥、超时和状态记录，不自行实现 token、切片或去重。单个任务默认不并发重入；上次仍在运行时，本次标记为 `skipped_overlap`。进程停止期间默认不补跑全部错过周期，管理员可从运行记录手工补采指定时间窗。

### 8.2 本地存储

单机默认使用 SQLite，启用 WAL、`busy_timeout` 和单写入队列；数据库文件默认位于实现仓 `var/` 或部署挂载目录，不写进 Git。数据访问基于 `database/sql` 和明确 repository，不使用隐藏 SQL 的重量 ORM。

建议最小表：

| 表 | 关键字段 | 作用 |
| --- | --- | --- |
| `collection_task` | `id`、`name`、`dataset`、`schedule`、`timezone`、`query_json`、`persist_mode`、`enabled` | 周期任务配置 |
| `task_run` | `id`、`task_id`、`trigger`、`status`、起止时间、请求快照、计数、错误摘要 | 手工/周期运行记录 |
| `query_slice` | `run_id`、时间片、状态、HTTP/业务码、`requestid`、记录数、SHA-256 | 切片审计与失败恢复 |
| `track_observation` | 内部主键、`dataset`、非唯一 `source_id`、`object_key`、经纬度、原始观测/入库时间、标准时间可空、`content_hash`、`attributes_json` | ADS-B/AIS 共用归一化观测；M1 Gate 前不静默覆盖 |
| `raw_response` | `run_id`、`slice_id`、`sha256`、压缩 JSON、字节数 | 可选 Raw 留存 |
| `task_watermark` | `task_id`、最大成功 `loadTime`、更新时间 | 增量水位线 |
| `observation_conflict` | `dataset`、`source_id`、关联观测、冲突类型、发现时间、状态 | 记录同 ID 的身份/时间/坐标冲突，禁止静默丢数据 |

M1 先跨日期和重跑窗口验证 `id` 稳定性。只有 ADS-B/AIS 分别证明同一 `id` 的身份与关键观测语义稳定后，才能增加 `UNIQUE(dataset, source_id)`；同 ID 同内容按 `content_hash` 判重，同 ID 内容更新保留版本，同 ID 关键身份冲突写入 `observation_conflict` 并阻断覆盖。若证据不足，使用追加版本和经验证的复合业务键，不能静默覆盖。未知字段保留在 `attributes_json`，公共检索字段使用独立列。时区未确认前，原始时间字符串为必存字段，UTC 列保持 `NULL`。

当出现多个应用实例、多个写入者、数据库位于网络文件系统、需要在线 HA 或数据量超过单机维护能力时，新增 PostgreSQL repository 和迁移，不通过兼容层强行让一套 SQL 同时适配两种方言。

### T4：真实小样本验收与收口

**目标：** 证明实现能在当前外部 API 上完成受控只读调用，并校准文档与默认值。

**修改范围：** 只允许修复验收发现的缺陷、更新实现仓 README 和本计划执行记录；不扩大到周期任务或落库。

**步骤：**

1. 核对 `LISTEN_ADDR`、`PUBLIC_ORIGIN` 与实际浏览器入口一致，并确认凭据只从本机 secret 文件注入，不写入命令输出、日志、前端或 Git；不再填写确认人、适用网络或本次有效期。
2. 从本机 secret 环境读取凭据，按提供方当前 HTTP 接口配置，分别执行一个短时间、小范围 ADS-B 和 AIS `direct` 查询。
3. 使用一个已知可能超页的 fake 场景验证 `complete`；真实 API 只对一个 14 位时间的受控窗口执行两次小规模 `complete`，两次间隔 5 分钟，不做压力测试。
4. 验收脚本在产品外比较两次真实结果的总数、ID 集和必要字段；差异只作为上游可变性的测试证据，API/UI 仍始终显示相同的 `best_effort` 与永久警告。

6. 从 canonical `PUBLIC_ORIGIN` 用浏览器复走原型主链路，检查 1536×960 和 390×844；确认浏览器请求 Host/Origin 与服务端配置一致。
7. 停服务冷启动再执行一次，证明实现不依赖热 token、热缓存或前端旧状态。
8. 更新本地实现仓 commit、本方案执行记录、残留风险和后续 M1 入口。

**验证：** 真实查询只做只读、低频、小范围调用。通过条件是 ADS-B/AIS 均返回可解释结果；`direct` 与单次上游响应一致；`complete` 多切片/fail-fast 契约全部通过；同窗实测无论是否变化，产品都只显示 `best_effort` 和永久警告；浏览器与日志不出现秘密。任何异常先停止扩大请求范围，按 `query_id` 和 fake 契约定位，不用重复真实调用碰运气。

**失败与回滚：** 外部 API 暂时不可用时保留 fake 契约结果，但 T4 标记未完成，不能把系统宣称为真实闭环。代码回退到最近通过的阶段；外部接口不产生写入，无数据回滚。

## 13. 实施前反证检查

1. 唯一实现落点是固定路径的独立本地 Git 仓；`dy-inta` 不承担运行代码，远端、CI 和发布权限也不再提前阻断 T0。
2. 本地凭据代理不依赖同源策略自证安全：Host 精确受限，非空 Origin 精确匹配，非回环缺 `PUBLIC_ORIGIN` 直接拒绝启动，非法请求不会触发上游。
3. 明文 HTTP 没有被包装成“认证安全”；上游 client 禁用 ambient proxy，但不再把提供方接口形态编码成使用方重复确认 Gate。
