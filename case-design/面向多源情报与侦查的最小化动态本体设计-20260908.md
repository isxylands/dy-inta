

### 面向多源情报与侦查的“最小化动态本体设计”

为了好理解、好开发、好落地，不需要复杂的几十层抽象，**只需要管好 5 个核心要素**：

`​`​`
                    ┌─────────────────────────┐
                    │      业务规则 (Rules)    │  (去重/主张分离/核验/升降级)
                    └────────────┬────────────┘
                                 ▼
┌──────────────────┐       ┌───────────┐       ┌──────────────────┐
│   对象 (Objects)  │ ◄────►│关系(Rel.) │ ◄────►│   属性 (Props)   │
│ (主体/目标/事件/信源)│       │(主张/因果)│       │(时空/置信度/版本) │
└──────────────────┘       └───────────┘       └──────────────────┘
                                 │
                                 ▼
                    ┌─────────────────────────┐
                    │      驱动动作 (Actions)  │  (矩阵生成/差异化预警/核验引导)
                    └─────────────────────────┘
`​`​`

#### 1. 核心对象（Objects / 实体）—— 最小化 4 大类

1. **行动主体（Actor）**：如 `美军中央司令部(CENTCOM)`、`伊朗革命卫队(IRGC)`、`约旦军方(Petra)`、`第三方东道国/机构`[cite: 2, 3]。
2. **物理目标/资产/区域（Target / Asset / Geo）**：如 `军事设施(Al Azraq基地)`、`民用/商业设施(科威特中资企业建筑、达米埃塔港)`、`船舶/飞机(带IMO的油轮、F-35)`、`地理咽喉(霍尔木兹海峡、曼德海峡)`[cite: 2, 3]。
3. **主张与事件（Claim / Event）**：
   * *单方主张*：如“伊方宣称摧毁3架F-35”、“伊方宣称击中并迫停2艘油轮”[cite: 2, 3]。
   * *确认事件*：如“约旦实际拦截5枚导弹”、“美军实施一轮对伊打击”、“UKMTO通报一艘油轮机舱受损”[cite: 2, 3]。
4. **观测信源/传感器（Observation Source）**：
   * *官方与媒体组*：约旦官方(Petra)、伊朗官方(IRNA)、美军(CENTCOM)、路透/美联社[cite: 3, 4]。
   * *运行态与传感器组*：海事(UKMTO/NAVAREA IX/IMO)、船流(PortWatch/GFW)、航迹(ADSB.lol/OpenSky)、气象(METAR)、遥感(NASA FIRMS热异常、Sentinel-1雷达/Sentinel-2光学)、公网(IODA)[cite: 2, 3, 4]。

#### 2. 核心属性（Properties）—— 解决时空与证据可信度

* **时间三态**：`event_time`（实际发生时间）、`publish_time`（信源发布时间）、`observed_at`（分析系统首次采集入库时间）[cite: 3, 4]。
* **时空精度**：`spatial_precision`（精确点位 vs 城市/国家级粗略区域）[cite: 2]。
* **证据元属性**：`independence_group`（独立信息链归组，防止重复转载误算权重）、`evidence_role`（触发线索 / 支撑证据 / 反驳证据 / 背景基线）[cite: 3, 4]。
* **态势研判属性**：`analytic_confidence`（分析置信度：高/中/低）、`status`（单方声明 / 明确争议 / 交叉确认 / 已失效）[cite: 2, 3]。

#### 3. 核心关系（Relationships）—— 建立线索网络

* **`makes_claim`（主体 $\to$ 主张）**：如 IRGC $\to$ 宣称击中 Ali Al Salem 基地[cite: 3]。
* **`supported_by / refuted_by`（主张 $\to$ 观测证据）**：
  * 如：“油轮受损” $\xrightarrow{\text{supported\_by}}$ UKMTO 报告[cite: 2]；
  * 如：“F-35被毁” $\xrightarrow{\text{refuted\_by}}$ CENTCOM 声明（且无商业卫星/东道国独立影像）[cite: 2, 3]。
* **`response_to`（事件 $\to$ 事件，因果链）**：如 美军7月30日空袭 $\xrightarrow{\text{response\_to}}$ 7月29日伊朗导弹袭击（**注：必须有官方明确因果声明或严密证据，严禁仅因时间先后自动连线**）[cite: 2, 3]。
* **`supersedes`（新研判 $\to$ 旧研判）**：版本替代关系（如“尚未确认美方打击” $\xrightarrow{\text{supersedes}}$ “美方打击已完成一轮闭环”）[cite: 4]。

#### 4. 业务规则（Rules / 研判逻辑）—— 固化专家的研判战法

* **规则 1：信源去重与归并**
  * *逻辑*：10 家网站转载同一篇美联社报道，系统自动归并为单一 `independence_group`，不可计算为 10 个独立佐证[cite: 3, 4]。
* **规则 2：主张与事实严格分离**
  * *逻辑*：若输入为参与方的“战果宣称”（如摧毁战机/基地全毁），若无第二类独立传感器（卫星/现场/中立通报）支撑，系统强制标记为 `低置信度/单方主张`，禁止直接上图成为“已摧毁”[cite: 2, 3]。
* **规则 3：传感器“未检出”的语义边界**
  * *逻辑*：FIRMS 热异常未发现火点 $\to$ 标记为“在 375m 分辨率及过境窗口内未检出”，不得自动推导为“事件未发生”[cite: 3, 4]。
* **规则 4：预警降级严苛准入**
  * *逻辑*：严禁仅因“24小时无新通报”或“油价单日下跌”自动下调预警；必须同时满足“双方书面/官方确认行动暂停 + 海峡无新增遇袭 + NOTAM空域限制缓解”等多条件[cite: 2, 3]。

#### 5. 驱动动作（Actions）—— 赋能业务决策

* **动作 A（自动生成交叉验证矩阵）**：自动输出如文档中的表格（主张、置信度、支持证据、反驳证据、缺失缺口）[cite: 2, 3]。
* **动作 B（生成差异化行动建议）**：根据事件影响对象，向管理层、出行保障、航运供应链、驻地安全分别派发防御预案[cite: 2, 3, 4]。
* **动作 C（反哺侦查与数据补链）**：如检测到“油轮遇袭主张”，系统自动生成数据缺口清单（提示需获取 IMO 编号、查询过境的 Sentinel-1 雷达影像）[cite: 3, 4]。
